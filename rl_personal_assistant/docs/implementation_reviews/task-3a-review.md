# Task 3A Independent Implementation Review

## Verdict

- **Spec compliance: FAIL**
- **Code quality: CHANGES_REQUESTED**

Task 3A is not safe to freeze as the Task 3B integration contract. The base `ActionCandidate` identity, frozen resolved wrapper, six-action closure, deterministic catalog sorting/limit, fixture-10 data migration, and public-chain stale-preview rejection are directionally correct. However, the current adapter cannot reset from the approved real public projection, the action mask disagrees with the frozen Task 1 scope/ledger semantics, and several public interfaces accept unverified or arbitrarily typed values that can carry private/oracle data or change the mask.

Scope: read-only inspection of `task-3-brief.md`, `task-3a-brief.md`, `task-3a-report.md`, the approved Task 0–2B briefs/reviews and production contracts, the three Task-3A modules and their tests, fixture 10, and the fixture-contract test change. Per instruction, tests were **not** rerun and no production/test file was edited.

## Findings

### Critical

1. **`ScriptedUserAdapter.reset` rejects the exact approved public scenario projection.** The binding contract says reset receives `project_public_observation(manifest)`. That projection contains the non-empty tuple of frozen `TaskStep` objects, each containing a frozen `Scope` ([scenarios.py](../../src/pa_rl/scenarios.py:238)). `_is_public_value` accepts only primitives, mappings, and tuple/list containers, so it returns false for every `TaskStep`; all ten real fixture resets therefore fail before Task 3B can construct an episode ([scripted_user.py](../../src/pa_rl/scripted_user.py:24), [scripted_user.py](../../src/pa_rl/scripted_user.py:54)). The adapter test hides the incompatibility by supplying `task_steps=()` instead of an actual projected manifest ([test_scripted_user.py](../../tests/test_scripted_user.py:11)).

   Required fix: validate the exact visibility-bound projection and its typed `TaskStep`/`Scope` public values (or consume an explicitly canonical public serialization produced by the projector without changing the Task-0 protocol). Add a test that calls `reset(project_public_observation(load_scenario(...)), seed)` for a real non-empty fixture.

2. **The mask is incompatible with approved authority semantics and can both suppress legal actions and admit stale/illegal ones.** There are four independent blockers in `build_action_mask` ([policy_interface.py](../../src/pa_rl/policy_interface.py:155)):

   - Task 1 emits `ScopeRelation.EXACT`, `NARROWER`, `BROADER`, or `DISJOINT`, where `NARROWER` means the operation is narrower than—and therefore covered by—the grant ([scope_matching.py](../../src/pa_rl/scope_matching.py:14), [scope_matching.py](../../src/pa_rl/scope_matching.py:58)). Execute instead recognizes the nonexistent public value `"covers"`, so a valid covering non-exact grant is masked ([policy_interface.py](../../src/pa_rl/policy_interface.py:170)).
   - Reusable active grants have `remaining_uses=None` by approved Task 1 semantics ([authorization.py](../../src/pa_rl/authorization.py:292)). Execute requires a positive integer, so fixture 2's reusable executions can never be selected.
   - `_view_for` returns `{}` for an unknown prior ID, but `valid_view = isinstance(view, Mapping)` treats that missing row as valid. Consequently any non-null, stale/foreign `prior_authorization_id` enables refresh; disjoint and unsuitable statuses are not rejected ([policy_interface.py](../../src/pa_rl/policy_interface.py:147), [policy_interface.py](../../src/pa_rl/policy_interface.py:180)). Disable likewise accepts every non-null status, although Task 3B may call `disable` only for a bound active record ([authorization.py](../../src/pa_rl/authorization.py:315)).
   - A request slot normally has neither selected nor prior authorization ID, so `_view_for` is empty and its same-scope do-not-reask branch can never fire. `PublicMaskState.preference_relation` is never read. A persistent denial therefore does not mask the prohibited re-ask path ([policy_interface.py](../../src/pa_rl/policy_interface.py:140), [policy_interface.py](../../src/pa_rl/policy_interface.py:178)).

   Required fix: use the frozen relation vocabulary (`EXACT`/`NARROWER` cover execution), treat `remaining_uses=None` as reusable rather than unusable, require an actually present related prior row for refresh and an active current row for disable, reject refresh on `DISJOINT`, and apply candidate-scope-specific re-ask preference to requests. Add table-driven tests for exact/narrower/broader/disjoint, one-time/reusable, every relevant lifecycle status, missing/stale IDs, persistent denial, and same-scope versus changed-scope re-ask.

3. **The observation/mask/event firewall is key-based but not value- or provenance-safe, so private/future/oracle inputs can enter public output or alter policy decisions.** Examples include:

   - `task_view` and `authorization_views` merely copy allowlisted keys; they do not validate phase/status/grant/relation domains, Boolean/count/expiry types, IDs, or nested values ([policy_interface.py](../../src/pa_rl/policy_interface.py:191), [policy_interface.py](../../src/pa_rl/policy_interface.py:217)). A private canary placed in an allowed field is returned verbatim. It can also change the mask: a non-empty private string in `primary_complete` is truthy and masks execute, while forged allowed-key status/relation/use values can enable it.
   - `request_context` uses a negative substring list rather than the existing visibility registry. It accepts omitted forbidden families such as scripted responses, legal/prohibited traces, expected termination, S-QSTN/rationale/minimal-scope/attack fields, and arbitrary dataclass/set/enum values because non-container objects fall through unchanged ([policy_interface.py](../../src/pa_rl/policy_interface.py:197)).
   - Public-event payload recursion checks mappings and lists only. A dataclass carrying private fields can be placed under a globally allowed key such as `public_id`; `canonical_hash` serializes the dataclass and the public record retains the object ([public_events.py](../../src/pa_rl/public_events.py:39), [contracts.py](../../src/pa_rl/contracts.py:259)). There are no event-type-specific exact payload schemas, so a rehashed `permission_requested` record can also carry globally allowed execution/grant fields and still verify.
   - `_interaction_history` checks only `isinstance(PublicEventRecord)` and never invokes `verify_public_event_chain`, so a directly constructed, unverified record is accepted into the observation and its counts ([policy_interface.py](../../src/pa_rl/policy_interface.py:229)).
   - `PublicMaskState` retains caller-owned mappings without a schema/freeze check, while `EnvironmentObservation` can be directly constructed without any validation. Thus the advertised immutable/public-only boundary holds only for one cooperative builder path, not for the exported records themselves.

   Required fix: define exact recursive schemas and value domains for every public projection and event type; accept only canonical JSON primitives/containers after explicit public projection; independently verify the full public chain before observation/history use; freeze and validate `PublicMaskState`; and make invalid direct construction impossible or validate it equivalently. Canary tests must place distinct private/future/oracle values inside *allowed field names* and typed/nested objects, then assert invariance/absence recursively from observation, catalog, mask, public events, and replay-policy input.

### Important

1. **Resolved-slot validation permits semantic duplicates and arbitrary public bindings/codes.** `ResolvedCandidate` checks only that required fields are non-`None`; it does not require string IDs, non-empty/canonical ID syntax, or positive allowlists for reason/target codes ([policy_interface.py](../../src/pa_rl/policy_interface.py:46)). Irrelevant cross-action fields are also permitted. Two request slots can therefore differ only by an irrelevant `authorization_id` and evade duplicate detection, or an allowed catalog field can carry a private dataclass/value. `CandidateCatalog.__post_init__` verifies contiguous slots and a caller-supplied hash but not canonical sort order or semantic uniqueness, so direct construction bypasses `build`'s protections ([policy_interface.py](../../src/pa_rl/policy_interface.py:110)).

   Required fix: enforce an exact required/forbidden binding matrix per action; validate task/auth IDs and positive reason/target code sets; define semantic uniqueness from only the action's meaningful binding tuple; and enforce the same uniqueness/order invariants in construction, not only in a convenience classmethod. Preserve the intentional `authorization_id=None` exception only for execute-shaped monitor-bypass testing. Add irrelevant-field duplicate, malformed-ID/code, direct-constructor, and post-selection binding-stability tests.

2. **Public-chain preview/commit is stale-head safe, but independent verification accepts invalid logical-time/type semantics.** `preview` is pure and `commit` rejects a record after another head is committed ([public_events.py](../../src/pa_rl/public_events.py:115), [public_events.py](../../src/pa_rl/public_events.py:129)); this part passes. However, `verify_public_event_chain` does not enforce exact integer types or positive 1-based logical steps. A recomputed first record with `sequence=True` and `logical_step=0` passes the equality/nondecreasing checks because `True == 1` and `0 < 0` is false ([public_events.py](../../src/pa_rl/public_events.py:140)). Combined with the absent per-event payload schemas above, a fully rehashed semantically invalid public history can pass.

   Required fix: validate every record field's exact type/domain independently, including non-Boolean positive sequence/logical step, event ID/hash grammar, and event-specific payload schema. Add fully recomputed negative cases, not only `dataclasses.replace` cases with stale hashes.

3. **The observation API cannot represent Task 3B's required closed post-observation.** Task 3B finalizes authority and appends expiry records at `H+1`, then requires a deterministic closed post-observation with no selectable live policy state. The builder rejects every `logical_step > horizon` and computes `horizon_remaining` as at least one ([policy_interface.py](../../src/pa_rl/policy_interface.py:274)). Reusing the step-`H` pre-observation would either omit final expiry history or attach `H+1` events to an observation claiming time `H`, breaking exact pre/post trace replay.

   Required fix: add an explicit closed-observation contract that permits only `logical_step=H+1`, sets `horizon_remaining=0`, carries the finalized public history, and exposes no live selectable catalog/mask (or another spec-approved exact representation). Add terminal and truncation construction tests before Task 3B begins.

4. **Tests do not exercise the adversarial cases needed to establish the claimed guarantees.** Current mask coverage uses only an exact one-time grant and asserts all six actions true, so it misses reusable, narrower coverage, stale refresh, terminal disable, and persistent denial ([test_policy_interface.py](../../tests/test_policy_interface.py:117)). The observation test proves that extra task/auth keys are dropped, but not that a private value under an allowed key is rejected; the mask “private canary” is placed only in ignored extra keys ([test_policy_interface.py](../../tests/test_policy_interface.py:135), [test_policy_interface.py](../../tests/test_policy_interface.py:153)). The event-chain tests do not rehash a semantically invalid positive-step/type/payload record. These are behavior gaps directly masking the production defects above.

## Passed checks

- Exactly the six frozen `ControllerAction` values remain; no deferred seventh action or alias was added.
- `ResolvedCandidate` preserves the unchanged Task-0 base candidate ID and base scope/action, and its frozen fields prevent ordinary post-selection reassignment.
- `CandidateCatalog.build` is insertion-order independent, rejects more than 16 inputs rather than truncating, and rejects exact duplicate semantic dictionaries.
- `PublicEventChain.preview` does not mutate; `commit` binds the current sequence/head and rejects a stale preview after an intervening append.
- The observation builder emits the required twelve top-level field names, and its builder-produced mappings are recursively frozen.
- History output is padded/bounded to `K=4`; the implemented response-rate formula uses `alpha=1.0`. Event-type-specific refresh counting still needs to be fixed/defined with the public-event schema.
- Fixture `10_timeout_truncation.json` contains the authorized three-decision trace, two `allow_once` answers, unrelated first/second scopes, horizon 3, no legal terminal success kind, and expected truncation. No other canonical fixture has the Task-3A modification timestamp. The present contract regression correctly rejects one answer against the new three-decision declaration; Task 3B still must prove a legacy one-response injection faults on the third request and cannot truncate successfully.

### Blocking findings

#### Important

1. **Expiry buckets are not bound to `PublicMaskState.logical_step`, allowing an impossible active row to enable refresh.** `_summary` checks only `active -> expiry_bucket=future` and `expired -> expiry_bucket=expired`; it has no logical step and never checks `expiry_step` against the current public time ([policy_interface.py](../../src/pa_rl/policy_interface.py:52)). Thus at logical step 3 an `active`/`future` row with `expiry_step=2` passes state construction. Execute happens to reject it through `expiry > logical_step`, but refresh ignores expiry and marks it valid if status/relation/preference otherwise qualify ([policy_interface.py](../../src/pa_rl/policy_interface.py:165), [policy_interface.py](../../src/pa_rl/policy_interface.py:169)). Conversely, the lifecycle test itself constructs `expired`/`expired-bucket` rows with future expiry step 4 at logical step 1 ([test_task3a_review.py](../../tests/test_task3a_review.py:101)). Validate `future` iff `expiry_step > logical_step` and `expired` iff `expiry_step <= logical_step` in `PublicMaskState`, then test both directions and the refresh result.

2. **Direct interaction history accepts semantically impossible counts.** `_interaction_view` verifies response `total=allow+deny` and recomputes smoothed rates, but never binds `counts.permission_choice` to response total or `counts.grant` to response allow ([policy_interface.py](../../src/pa_rl/policy_interface.py:235)). More decisively, four padding records—which prove the complete history is empty—can be paired with arbitrary nonzero prompt/grant/revocation counts and still pass.
