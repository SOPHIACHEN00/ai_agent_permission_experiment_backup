# Logistic-regression permission baselines

Predict one of the four original human permission responses from task, tool and
data-type features. These supervised baselines do not decide or grant actual
execution permission.

| Model | Implementation |
| --- | --- |
| Flat four-class LR | One multinomial classifier for the four labels |
| Ordinal LR | Three independent cumulative-threshold binary classifiers; not a shared-slope proportional-odds model |
| Factored LR | Separate allow/deny and persistent/one-time predictions, combined into a label |

`build_dataset.py` retains all four labels from upstream `user_study.json`.
`run_four_label_benchmark.py` implements the fixed baselines and shared splits,
features and metrics. `tune_four_label_classifiers.py` performs inner validation
within the outer training split.

From the repository root:

```bash
python -m pip install -r requirements.txt
python classification/run_four_label_benchmark.py --data data/processed/four_label_dataset.csv --split participant_heldout --out outputs/lr_baseline
python classification/tune_four_label_classifiers.py --data data/processed/four_label_dataset.csv --splits participant_heldout --out outputs/lr_tuned
```

Retained final evidence is in [results/nested_tuning](results/nested_tuning/), with
separate participant-held-out and row-stratified results. The former holds out
41 of 201 participants; the test set contains 3,323 rows. The latter permits
participant overlap and should not be described as unseen-user evaluation.
Compact metrics, selected parameters and confusion matrices are retained;
per-row predictions and copied source trees are generated by reproduction runs.

The ordinal ordering is a modeling convention; allow/persistence responses are
not interchangeable with the Agent's four controller actions. A higher label
matching score does not establish lower actual data exposure or task success.
