# 当前方法：有真实授权约束的个体权限控制

## 系统要解决什么

Agent 接到任务后，需要决定申请什么权限、用什么范围执行工具、什么时候关闭执行门。
学习目标同时考虑完成任务、减少额外数据读取或披露、减少多余追问和闲置执行门。
真实授权由 Ledger 和 Reference Monitor 强制执行，预测某人“可能同意”不能产生授权。

完整英文定义与代码映射见 [METHOD.md](METHOD.md)。

## 外部角色与 Agent 内部流程

- **人类 / S-QSTN：** 接收权限请求，返回实际回答。S-QSTN 是人类侧模拟器，其隐藏画像不直接交给 policy。
- **Agent：** Planner 根据任务、工具结果和反馈提出下一次调用；Compiler 校验参数并形成合法候选；DDQN 从候选中选一个；Dispatcher 执行动作并更新授权状态。
- **Mock tools：** 执行最简本地读写，返回工具结果和回执。工具结果告诉 Planner 发生了什么，回执支持效果和授权审计。
- **Evaluator：** 根据实际效果、任务要求和交互记录算成功与成本，训练时产生 reward。它与执行前检查授权的 Monitor 职责不同。

任务循环是“计划 → 选择 → 行动 → 观察”；学习循环是“实际经历 → reward → replay → 更新参数”。
目前可复现的功能和 DDQN 诊断使用脚本 Planner 与明确标注的固定回答；代码保留 LLM Planner 接口和 S-QSTN 桥接接口。

## C、G、P 与四种动作

| 对象 | 含义 |
| --- | --- |
| C — Consent | 用户实际回答、权限范围和有效期。跨任务复用不延长原有效期 |
| G — Gate | 本任务当前打开的执行门，需要有效 C 支持 |
| P — Permit | Monitor 对一次具体调用签发的一次性执行凭据 |

| 动作 | 做什么 |
| --- | --- |
| REQUEST | 缺授权时向用户申请；已有有效 C 时可直接打开对应 G |
| EXECUTE | 尝试调用工具；Monitor 再检查完整 C/G 并绑定 P |
| RELEASE | 关闭 G；有效的长期 C 仍保留 |
| END | 在协议允许的完成或停止条件下结束当前任务 |

Scope 是具体权限范围，包括工具、接收方、读取或写入方向及数据字段；执行还绑定资源和参数。
同一种动作可以有多个不同 scope 的候选。DDQN 输出的是某一个具体候选，不是任意生成工具调用。

## RL 学什么

RL 输入是当前公开 state、候选动作特征和合法性 mask。State 包含任务进度、已观察回答、有效 C、当前 G 等；
候选特征包含动作类型、字段数量、范围身份及相关历史回答。网络给每个候选一个 Q 值，评估时选合法候选中 Q 最大的一个。
训练时还会按配置进行探索，并用实际发生的 transition 更新网络。

一个 query 是一个 episode，但里面可以有很多次控制决策。每次决策都能形成一条 transition。
任务结束时停止该 episode 的价值自举，不把下一题奖励接到上一题。当前任务内 gamma=1。
同一用户的历史、有效 C、模型和 replay 跨 query 保留，G 只属于当前任务。
当前代码给不同用户分别维护模型和 replay；“共享底座＋个体适应”仍是讨论中的改进方向。

## Reward

$$R = \alpha S - \beta F - \lambda_r E^r - \lambda_d E^d - \lambda_m M - \lambda_g K.$$

- S/F：任务成功或失败，终局只结算一次。
- Eʳ/Eᵈ：相对预先声明的任务要求，实际多读取或多披露的字段实例。
- M：Agent 路径增加的额外权限询问；PB 另外统计全部权限消息。
- K：指定检查点上闲置的有效 G 键数累计，不是对长期 C 收费。

收回 G 可以降低后续 K，但不能撤销已经发生的数据披露。任务失败保留在完成率分母里。
权重由实验配置明确给出。固定三题诊断中成功/失败幅度为 1，额外读/披露/询问为 0.01，闲置 G 为 0.001；这些不是已证明最优的研究参数。

Double-DQN 用 online 网络选下一候选、target 网络评价该候选，终局直接用实际 reward。
Replay、Huber loss、梯度裁剪和 target 同步均已实现。可选增强包括公开后果特征、动作类型均衡探索、观测 n-step 和同用户经验保留。
三题纯 DDQN 对照不使用规则示范或额外动作排序监督。

## 数据和证据要如何理解

65 是任务 query 类型数。三种 persona 各跑一遍可形成 195 个基本任务组合；一题内多次权限决定产生更多 transition。
原始四标签调查数据另有 16,361 条回答和 201 位参与者，用于 LR/MAB 等基线；这些回答不会自动变成完整 Agent 轨迹。
S-QSTN 的三种 persona 是模拟设定，不是三位真实用户，也不代表真实用户偏好的全部变化。

目前已经实现四动作流程并验证真实 DDQN 参数更新。关闭探索后的执行仍不稳定，个性化收益尚未得到验证。
现有三题训练诊断、LR/MAB 预测结果、S-QSTN 单轮分布评测分别回答不同问题，不能合并成一个 Agent 成功率。
