## 0. 写作提纲与主张约束

本节采用以下五段论证顺序：

1. 定义研究对象：持续服务同一用户的单个个人助理，以及阶段性变化的数据需求。
2. 定义决策对象：访问范围、询问与复用，以及真实授权的生命周期。
3. 定义长期交互：逐任务学习用户特定策略；区分持续学习与持续授权。
4. 定义目标：在授权约束下，联合考察任务完成、用户打扰和信息暴露。
5. 定义实验边界：有状态 mock、受控任务、模拟人类，以及有限的安全保证。

动笔前的主张意图清单：

- 本文研究的是序贯权限决策，不以单次同意／拒绝预测准确率代替端到端效果。
- 每名用户独立适应，不声称通用用户偏好模型、跨用户迁移或未见用户泛化。
- 权限策略必须受真实授权约束；预测同意、旧任务中的同意和 ESCALATE 澄清均不产生当前执行权。
- 权限收缩必须改变实际有效授权；窄读取与授权收缩分别计量。
- 任务完成、打扰和数据暴露均需报告；不得通过丢弃失败任务制造收益。
- DDQN、S-QSTN 和 harness 是方法与实验实现，不是研究问题本身。
- 不把接口测试、权重更新或可行的手写缩权轨迹写成已学习到缩权的证据。
- 不将字段级权限检查写成任意语义内容的防泄漏保证。

## 1. 可用于论文的正文草稿

### 1.1 研究场景与核心问题

本文考虑一个持续服务同一用户、通过工具访问用户数据并完成多步任务的个人助理智能体。用户先提出任务目标，随后在执行过程中响应权限请求或提供澄清。智能体在不同任务阶段可能需要不同的数据范围：某一步只需要文档标题，另一阶段需要读取其中的私人备注，而后续步骤又仅需要标题。任务指令本身不被视为对所有相关数据的无限授权。

权限决策因此具有跨步骤的后果。重复申请最小范围的访问可能增加用户打扰；申请可复用的宽权限可以减少后续询问，但也可能使当前已不需要的数据继续处于可访问状态。随着任务推进，控制器需要决定何时申请权限、申请多大范围、何时复用已有授权，以及何时收缩或禁用不再需要的授权。本文研究的核心问题是：**在真实授权约束下，如何通过与同一用户的持续交互学习这些决策，使智能体在完成任务的同时，减少用户打扰和不必要的信息暴露？**

### 1.2 决策对象与执行约束

我们将任务规划与权限决策分离。任务语言模型依据任务目标和可见执行历史提出工具调用；权限控制器在调用执行之前，对其访问范围和授权使用方式作出决策。访问范围描述工具、资源、数据字段、操作、用途及接收者等属性。有效授权还受到状态、有效期和剩余使用次数等生命周期条件约束。环境提供公开的工具接口与任务阶段信息，但控制器不直接获得评估器标注的必要字段集合。

控制器的决策空间包含申请授权、刷新或变更既有授权、在有效授权下执行、禁用本地授权、拒绝并说明原因，以及请求用户澄清六类动作。每个动作可以绑定不同的访问范围或授权记录，因此决策对象是“动作类型及其参数”，而不只是六个抽象标签。权限扩张以及当前实现中的授权刷新均须获得与请求匹配的用户同意。澄清本身不授予权限。

授权账本（ledger）记录已经发生的授权事实，执行监控器（reference monitor）在工具执行前独立检查授权是否有效、是否覆盖本次调用，并核验使用次数及执行绑定。学习策略不能自行生成授权，也不能凭借对用户偏好的预测绕过检查。收缩权限意味着原有宽授权被实际替换或禁用，从而减小后续可访问范围；在宽授权仍然有效时只执行一次窄读取，并不等于授权已经收缩。

### 1.3 用户特定的持续交互

本文以单个用户的连续任务序列作为学习场景。系统不能预先获得该用户完整的权限偏好，只能依据实际交互中可观察的权限回答、执行结果及任务反馈调整策略。对于每名用户，学习参数与经验在任务之间保留；不同用户的学习状态相互隔离。因此，本文关注同一用户上的在线权限决策适应，而不是训练面向不同用户的通用偏好模型。

持续学习与持续授权是两种不同的状态。本研究的首版设定允许学习状态和适用的人类交互记忆跨任务延续，但每个任务重新建立授权账本和工具环境。上一任务中的同意不能直接用于下一任务。该设计使我们能够考察历史交互是否帮助当前权限决策，同时避免将历史偏好误用为永久访问许可。

### 1.4 任务完成、效率与隐私的联合目标

我们将效率定义为完成用户任务所需的交互成本，主要考察任务完成率和用户打扰次数，并辅助报告控制步骤与任务语言模型调用次数。用户打扰同时包含新授权请求、授权刷新请求和澄清请求。偏好适应是改善决策的潜在机制，而不是效率指标本身；拒绝所有访问而无法完成任务，不被视为高效率策略。

隐私侧区分潜在访问面与实际数据暴露。潜在访问面使用有效授权的字段范围在控制步骤上的累计值，以及任务结束时仍然有效的授权范围衡量。实际数据暴露统计工具实际返回或发送的字段，并根据任务阶段的独立必要性标注识别多余字段实例。必要性标注仅供评估器使用，不作为策略输入。用户同意访问某些数据，并不意味着这些数据对当前阶段均有必要。

本文的目标是在遵守授权边界的前提下，改善任务完成、用户打扰与上述暴露指标之间的权衡。当前实验将其具体化为：在给定打扰预算和授权暴露预算内，提高任务完成且执行完整性检查通过的概率。通过不同预算下的对照，可以进一步检验策略是否改善这一权衡，而不是只将成本从一个指标转移到另一个指标。所有失败与预算中止任务均应保留；成功任务上的成本可另外报告，但不能代替全体任务结果。

### 1.5 实验实例与研究边界

我们使用有状态本地 mock 工具构造受控执行环境。工具调用会实际改变合成状态或返回指定字段，任务是否完成由独立的结果检查器判断。任务语言模型、权限控制器、授权账本与执行监控器共同形成闭环。S-QSTN 仅作为有记忆的人类回答方，回应权限请求与澄清，不承担任务规划，也不向控制器提供隐藏用户画像或评估答案。每用户独立的 DDQN 是这一问题设定下的候选学习方法。

本研究假设授权账本、执行监控器和工具入口位于可信运行边界内，所有受测工具调用都经过该边界。我们不假定任务语言模型提出的每次调用都必要或已经获准。当前隐私指标衡量字段级访问与披露，不等同于语义层面的保密保证：例如，合法消息正文可能包含此前合法读取的敏感内容。撤销授权也不能消除模型已经读到的信息。因此，本研究首先考察受控任务中的动态访问最小化与授权约束，不将其表述为对任意第三方工具、任意内容流或全部智能体安全威胁的解决方案。

## 2. 可选的形式化表述

这一部分可在论文方法成型后放入 Problem Formulation。它描述当前实现对应的目标，不声称已经证明 Markov 性或求得最优策略。

对于固定用户 \(u\)，令 \(\tau_{u,1},\ldots,\tau_{u,K}\) 为连续任务。在任务 \(k\) 的控制步骤 \(t\)，权限策略从当前合法候选集合中选择：

\[
a_{k,t}=\pi_{\theta_u}\bigl(o_{k,t},\mathcal C^{\mathrm{valid}}_{k,t}\bigr).
\]

\(o_{k,t}\) 表示可观察信息的数值摘要，包括公开任务进度、待执行调用的范围特征、授权状态、当前任务的权限回答摘要，以及剩余预算。当前实现为 38 维状态和 35 维候选特征；维度属于方法细节，不是问题定义所必需的假设。跨任务经验主要通过独立的 \(\theta_u\) 和 replay 保留，不应写成控制器直接读取 S-QSTN 的全部长期记忆。

令 \(G_{k,t}^{\mathrm{eff}}\) 为控制决策执行前仍有效的授权集合，\(F(g)\) 为授权 \(g\) 的字段集合。当前授权暴露代理为：

\[
E_k=\sum_{t\in\mathcal T_k^{\mathrm{charged}}}
        \sum_{g\in G_{k,t}^{\mathrm{eff}}}|F(g)|.
\]

它按接受的合法控制决策计量，而不是按墙钟时间计量。重叠授权按记录分别计数，通配符不展开为真实数据量，等待用户回复不额外累计。当前实现先计本步暴露，再检查预算，因此超预算停止时可以记录到 \(E_k>B_E\)，但不会据此额外执行工具。该指标称为“授权暴露代理”比称为“隐私损失”更准确。

设 \(S_k\) 表示正常完成且业务 oracle 通过，\(V_k\) 表示全链路完整性检查通过，\(I_k\) 为总打扰次数。当前优化目标可对应为：

\[
\max_{\pi_{\theta_u}}\quad
\mathbb E\!\left[
\mathbf 1\{S_k\land V_k\land I_k\leq B_I\land E_k\leq B_E\}
\right].
\]

代码使用满足上述条件时为 1、否则为 0 的终局奖励，中间奖励为 0。**这不是已实现的加权连续奖励，也没有将实际多余披露项直接加入奖励。** \(V_k\) 仅表示已实现的完整性检查，不包含未实现的通用语义信息流保证。

独立执行约束为：每次真正执行的工具调用必须有有效、未耗尽且覆盖该调用的授权，并通过 monitor 的执行绑定检查。该约束由可信执行层强制检查，不通过“越权扣一点 reward”来代替。

因此，单一预算下的成功率只能回答一个预算点的问题。若要形成更强的 privacy–efficiency trade-off 结论，还需报告多预算点或可比任务完成水平下的成本与暴露比较，并分别检查潜在访问面和实际披露。

## 3. 从此前实验到当前论文定位

我们自己的早期 ICL／classification 任务侧重从给定上下文预测权限回答；当前问题增加了工具执行、授权状态与后续决策的依赖。论文主线可以表述为：从孤立的权限回答预测，走向固定用户上的序贯访问范围与授权生命周期控制。这是对本项目研究对象变化的概括，不是对整个文献领域的新颖性判断。

- **Problem setting：** 固定用户持续交互中的动态权限范围与生命周期控制。
- **Method：** 每用户独立 DDQN，加上与学习策略分离的授权账本和执行监控器。
- **Evaluation harness：** 任务 LLM、模拟人类、有状态 mock、oracle 和审计闭环。
- **待验证的效果：** 在明确的授权约束下，减少无效打扰和不必要暴露，并维持或提高任务完成表现。

不要把“搭了一个 harness”直接等同于已经证明方法有效。也不要把“每用户独立 DDQN”本身等同于已学会用户偏好。当前编码以范围关系、字段数量和权限回答统计等特征为主，不能先行声称学得任意语义类别的细粒度偏好。

推荐用语：**面向固定用户的在线权限决策适应**、**用户特定的动态权限控制**、**授权约束下的任务完成—用户打扰—数据暴露权衡**。
