# S&P 四标签分类：数据来源与处理链

> 核查状态：2026-08-09 已按当前仓库逐项复核。本文中的行号对应本次核查时的文件版本；脚本后续改动时，应优先按函数名定位并同步更新行号。

## 1. 一句话结论

当前经典分类实验的四标签数据不是直接使用 S&P 上游仓库的 `processed_dataset.json`，而是由本项目的 `build_dataset.py` 从匿名化的原始用户研究文件 `user_study.json` 重新展开得到。重建结果为 **16,361 行、201 名有效参与者、65 个 query**，并保留了全部四种权限响应。

这里的“raw”特指论文作者发布的、已经匿名化的用户研究导出文件，并不等同于 Prolific 或问卷平台的原始后台日志。

## 3. 为什么不能从上游 `processed_dataset.json` 做四分类

上游说明明确写明，`processed_dataset.json` 只保留满足“至少 5 次 always share 或 never share”的 181 名参与者（`ai_agent_permission_experiment/external/ai-agent-permissions/data/README.md:28-29`）。对文件内容的直接审计还显示：

| 响应文本 | 在上游 processed 中出现次数 |
|---|---:|
| `No, never share` | 2,319 |
| `No, but ask me next time` | 0 |
| `Yes, but ask me next time` | 0 |
| `Yes, always share` | 5,244 |

因此该文件已经丢失四分类所需的两个中间标签。它适合上游自己的二值/极端偏好任务，但不能恢复本项目的四标签目标。四分类必须回到 `user_study.json`，并以 raw 文件中的实际响应字符串为准；上游 README 中的自然语言简写不能替代代码中的精确映射。

可重复执行的只读核查命令：

```powershell
$UpstreamProcessed = 'ai_agent_permission_experiment\external\ai-agent-permissions\data\processed_dataset.json'
@(
  'No, never share',
  'No, but ask me next time',
  'Yes, but ask me next time',
  'Yes, always share'
) | ForEach-Object {
  $ResponseText = $_
  $ResponseCount = (
    Select-String -Path $UpstreamProcessed -Pattern ([regex]::Escape($ResponseText)) -AllMatches |
      ForEach-Object { $_.Matches.Count } |
      Measure-Object -Sum
  ).Sum
  [pscustomobject]@{ response = $ResponseText; count = [int]$ResponseCount }
}
```

## 4. 从 raw 到逐行四标签数据的精确处理链

构建脚本是 `ai_agent_permission_experiment/src/build_dataset.py`。

### 4.1 加载与参与者筛选

1. 加载 `user_study.json`、`queries.json` 与 `data_types.csv`：`build_dataset.py:100-112`。
2. 只保留 `Valid is True` 的参与者：`build_dataset.py:118-120`。
3. raw 中共有 203 人；实际保留 201 人，排除 2 名 `Valid != true` 的参与者。
4. 参与者画像字段来自 `uuid`、年龄、性别、教育、AI 熟悉度/频率/信任、隐私重要性和关注 domain：`build_dataset.py:122-134`。
5. `concern_domain` 被按 `|` 拼接成一个字符串，而不是拆成多个独立列：`build_dataset.py:123`。

### 4.2 行展开单位

脚本遍历每名有效参与者的 `task3`；再遍历每个响应中 `answer` 的每个键值对：`build_dataset.py:136-164`。

- `answer` 的键按第一个逗号拆为 `(tool, raw_data_type)`：`build_dataset.py:93-97`；
- 每个 `(participant, query, tool, raw_data_type)` 权限响应生成一行；
- 若 query id 不存在或标签不在映射表中则跳过并计数；本次结果中两类跳过数均为 0：`dataset_summary.json:32-34`。

所以 16,361 行不是 16,361 个独立参与者，而是 201 人各自贡献的重复测量。评估时必须把参与者当作聚类单位，详见 `01_评估协议与防泄漏约定_zh.md`。

### 4.3 四标签映射

映射定义在 `build_dataset.py:11-16`，并被写入每一行的 `label_text` 与 `label_id`（`build_dataset.py:161-162`）。

| `label_id` | raw 响应文本 | 当前访问因子 | 未来持续性因子 | 行数 |
|---:|---|---|---|---:|
| 0 | `No, never share` | deny | persist deny | 2,361 |
| 1 | `No, but ask me next time` | deny | ask again | 1,720 |
| 2 | `Yes, but ask me next time` | allow | ask again | 7,056 |
| 3 | `Yes, always share` | allow | persist allow | 5,224 |

计数证据：`classification_experiments/artifacts/rebuilt_data/dataset_summary.json:5-10`；映射证据：同文件 `:26-30`。

### 4.4 query 与数据类型元数据

每行通过 `query_id` 连接 `queries.json`，补入 `query` 与 `domain`；通过 `data_types.csv` 补入 `generic_data_type`，并构造 `necessity_status`。

`generic_data_type` 的映射规则（`build_dataset.py:42-63`）是：

1. 对字符串去首尾空白、转小写、合并连续空格；
2. 优先做目录中的精确匹配；
3. 未命中时做包含关系回退；
4. 仍未命中则写为 `Unknown`。

本次输出中 `generic_data_type == "Unknown"` 有 **1,911 / 16,361（11.68%）**。这是“通用数据类型映射失败/未覆盖”，不要与下面仅有 80 行的 `necessity_status == "unknown"` 混淆。包含关系回退是启发式规则；若目录或命名改变，必须重新审计其歧义和 `Unknown` 比例。

`necessity_status` 的构造规则位于 `build_dataset.py:70-90`：

- 从 `datatype`、`data_tool1`、`data_tool2`、`data_MIRA` 汇总必要数据类型；
- 从对应的 `*_incorrect` 字段汇总显式错误数据类型；
- 按“`incorrect_explicit` 优先、其次 `necessary`、否则 `unknown`”赋值。

最终计数为：

| `necessity_status` | 行数 |
|---|---:|
| `necessary` | 14,133 |
| `incorrect_explicit` | 2,148 |
| `unknown` | 80 |

证据：`dataset_summary.json:11-14`。该字段来自作者为 query 提供的必要/错误数据标注，具有潜在的部署期 oracle/特权信息风险，不能默认认为线上可得；具体约定见评估协议文档。

### 4.5 输出与校验

脚本写出 CSV、`dataset_summary.json` 和 `label_mapping.json`：`build_dataset.py:172-190`。硬校验位于 `build_dataset.py:193-202`：

- `participant_id`、`query_id`、`tool`、`raw_data_type`、`label_id` 必须存在且非空；
- 输出必须同时包含标签 `{0,1,2,3}`。

CSV 的 18 个字段为：

```text
participant_id, age, gender, education,
ai_familiarity, ai_frequency, ai_trust, privacy_importance, concern_domain,
query_id, query, domain, tool, raw_data_type, generic_data_type,
necessity_status, label_text, label_id
```

## 6. 进入分类器前的特征管线

特征定义在 `ai_agent_permission_experiment/src/run_four_label_benchmark.py:32-70`：

| 分支 | 输入字段 | 处理 |
|---|---|---|
| 文本 | `query`, `tool`, `raw_data_type`, `generic_data_type`, `domain` | 先以空格拼接；TF-IDF word 1-2 gram，`min_df=2`，`max_features=20000` |
| 类别 | `domain`, `tool`, `generic_data_type`, `necessity_status`, `gender`, `education`, `concern_domain` | One-hot，未知类别忽略 |
| 数值/序数 | `age`, `ai_familiarity`, `ai_frequency`, `ai_trust`, `privacy_importance` | 转数值；缺失写 `-1`；原值直通，不标准化 |

注意：`domain`、`tool`、`generic_data_type` 同时进入文本与 one-hot 分支，这是当前基线的既定设计。`participant_id`、`query_id`、`label_text`、`label_id` 均不作为特征。尽管没有直接输入 `participant_id`，人口统计字段和 `concern_domain` 在 row split 中仍可能成为参与者指纹；不能据此宣称对新参与者泛化。

预处理必须只在相应训练数据上拟合：基线用 `Pipeline` 封装（`run_four_label_benchmark.py:83-89`）；嵌套调参在每个 inner fold 中执行 `fit_transform(fit)` 与 `transform(validation)`（`tune_four_label_classifiers.py:220-222`）。禁止在全数据上先拟合 TF-IDF/one-hot 再切分。

## 7. 安全重建命令

以下命令从 `Week67` 根目录运行，只写入带时间戳的新目录，不覆盖 canonical 数据或既有实验产物。执行前需在当前 Python 环境安装 `ai_agent_permission_experiment/requirements.txt`。

```powershell
$RebuildTag = Get-Date -Format 'yyyyMMdd_HHmmss'
$RebuildRoot = Join-Path 'classification_experiments\artifacts' "manual_rebuild_$RebuildTag"
$RebuildCsv = Join-Path $RebuildRoot 'four_label_dataset.csv'

if (Test-Path $RebuildRoot) {
  throw "Refuse to reuse existing output directory: $RebuildRoot"
}

python ai_agent_permission_experiment\src\build_dataset.py `
  --repo ai_agent_permission_experiment\external\ai-agent-permissions `
  --out $RebuildCsv

$ExpectedDatasetHash = '4A6F61191318EAA79BA2FAC1AB80E6FB850E099F1F0178EEF2F53B3B527FE463'
$ActualDatasetHash = (Get-FileHash -Algorithm SHA256 $RebuildCsv).Hash
if ($ActualDatasetHash -ne $ExpectedDatasetHash) {
  throw "Dataset hash mismatch: $ActualDatasetHash"
}

Get-Content -Raw (Join-Path $RebuildRoot 'dataset_summary.json')
Import-Csv $RebuildCsv |
  Group-Object generic_data_type |
  Sort-Object Count -Descending |
  Select-Object Name, Count
```

若 raw 输入、构建逻辑或 pandas 的 CSV 序列化行为被有意修改，哈希可能合理变化；此时不能简单替换期望值，必须同时解释变更、重新核对全部计数，并保留旧快照。

## 8. 后续维护约定

每次增加数据或修改构建逻辑时，至少更新：

1. 三项真正输入文件与生成 CSV 的 SHA-256；
2. 总行数、参与者数、query 数、四标签计数；
3. `generic_data_type == Unknown` 与三种 `necessity_status` 的计数；
4. 跳过标签与缺失 query 的记录；
5. 特征字段、预处理参数及 oracle 可用性说明；
6. 本文的函数定位和行号。

任何后续分类模型都应读取同一份、哈希明确的四标签 CSV；若使用不同数据版本，必须在新的实验文档中声明，不能与本快照的分数直接比较。
