# S&P 四标签分类：评估协议与防泄漏约定

> 生效日期：2026-08-09。本文是后续经典分类基线的默认协议。若新实验偏离其中任何一项，必须在该实验的 Markdown 记录中显式说明原因和影响。

## 1. 核心规则

1. **主结果使用 `participant_heldout`**；`row_stratified` 仅作为偏乐观的补充结果。
2. **外层 test 不参与特征设计、阈值选择、超参数选择或模型选择**。所有选择只在外层 train 内完成。
3. `participant_heldout` 的 inner CV 必须按 `participant_id` 分组；同一参与者不得跨 inner fit/validation。
4. TF-IDF、one-hot 词表/类别表和任何数据驱动预处理都必须在每个训练 fold 内拟合。
5. 主选择指标是 macro-F1；安全风险率方向相反，越低越好。
6. 每个实验必须声明是否使用 `necessity_status` 等部署期可能不可得的 oracle/特权特征。
7. 同一参与者贡献多行，统计不确定性不得把行当作独立样本。
8. 旧 test 已被历史调参表触碰；当前固定 test 只能称为“冻结的历史 benchmark test”，不能再声称是从未查看的最终确认集。

## 2. 两种外层划分的事实与解释边界

划分实现位于 `ai_agent_permission_experiment/src/run_four_label_benchmark.py:163-178`，两者都使用 `test_size=0.2` 与外层种子 42。

本文把 context 定义为三元组 **`(query_id, tool, raw_data_type)`**。

| 协议 | 实现 | train / test 行 | train / test 参与者 | 参与者重叠 | query 重叠 | test context 在 train 中的重叠 | 可以支持的解释 |
|---|---|---:|---:|---:|---:|---:|---|
| `row_stratified` | 按 `label_id` 分层的逐行随机切分 | 13,088 / 3,273 | 201 / 201 | **201** | 65 / 65 | **369 / 369** | 同一批参与者、基本相同场景中的新响应行 |
| `participant_heldout` | `GroupShuffleSplit(groups=participant_id)` | 13,038 / 3,323 | 160 / 41 | **0** | 65 / 65 | **373 / 373** | 新参与者在已知 query/context 目录上的响应 |

计数证据：

- `classification_experiments/artifacts/nested_tuning_20260809/row_stratified/run_config.json:6-16`；
- 同文件 `:17-41` 还显示 row inner folds 的参与者重叠均为 201；
- `classification_experiments/artifacts/nested_tuning_20260809/participant_heldout/run_config.json:6-16`；
- 同文件 `:17-41` 显示 participant inner folds 的参与者重叠均为 0。

### 2.1 为什么 row split 只能做补充

row split 中所有 201 名参与者同时出现在 train 和 test。虽然 `participant_id` 没有直接输入模型，年龄、性别、教育、AI 使用画像、隐私态度和 `concern_domain` 等稳定字段可能共同构成参与者代理特征；同一人的多行也具有相关性。因此该分数通常比“新参与者泛化”更乐观，不能作为论文主结论。

### 2.2 participant heldout 仍然没有解决什么

participant heldout 完全阻断参与者重叠，但 65 个 query 和全部 373 个 context 仍在两侧共享。当前文本特征包含 query/tool/data type，模型可以学习或记忆已知场景模式。因此它评估的是：

> 对未见过的参与者，在已经见过的场景与数据访问组合上预测权限偏好。

它不评估新 query、新 tool-data 组合或新 domain 的泛化。若要做这类主张，必须新增按 `query_id` 或 context 分组的外层划分，并确保相同 query 文本不跨 train/test；不得把当前 participant-heldout 分数改名为 query-heldout 分数。

## 3. 旧调参为何被认定为 test-touched

旧文件位于：

- `ai_agent_permission_experiment/results/tuning/flat_lr_tuning_row_stratified.csv`；
- `ai_agent_permission_experiment/results/tuning/flat_lr_tuning_participant_heldout.csv`；
- 合并表 `ai_agent_permission_experiment/results/tuning/flat_lr_tuning_all.csv`。

它们尝试 Flat LR 的 `C={0.1,0.3,1,3,10}` 与 `class_weight={balanced,None}`，但当前仓库中未找到与旧表配套的独立 validation 结果、fold manifest、run config 或原始 runner。更直接的证据是，旧表中 baseline 候选的五项数值与外层 test 结果逐值相同：

| split | 旧 tuning 行 | 对照 test 行 | accuracy | macro-F1 | QWK | over-sharing | persistent over-allow |
|---|---|---|---:|---:|---:|---:|---:|
| row | `ai_agent_permission_experiment/results/tuning/flat_lr_tuning_row_stratified.csv:2`，`C=1, balanced` | `ai_agent_permission_experiment/results/row_stratified/metrics.csv:2` | 0.466544 | 0.432445 | 0.386593 | 0.313725 | 0.223519 |
| participant | `ai_agent_permission_experiment/results/tuning/flat_lr_tuning_participant_heldout.csv:6`，`C=1, balanced` | `ai_agent_permission_experiment/results/participant_heldout/metrics.csv:2` | 0.406560 | 0.366901 | 0.309409 | 0.430425 | 0.211760 |

因此旧表至少是在同一个外层 test 上评估多个候选；若据表中最大 macro-F1 选择 `C`，test 就承担了 validation 的角色。旧表可以作为探索性 test sweep 保存，但不能作为“无偏选出的最佳参数”证据。

进一步的限制是：即使 2026-08-09 的新调参代码现在不读取 test 来选参，模型开发者已经在历史上看过这个固定 test 的结果。新流程修复了**本次运行内部**的直接泄漏，却不能让历史 test 重新变成从未触碰的确认集。若后续要做强确认性结论，应使用新的预注册参与者外层 folds/新 holdout，或报告完整 nested group CV，而不是继续围绕 seed 42 的单一 test 迭代。

## 4. 新的内层选参与外层测试规则

无 test 选参的实现为 `ai_agent_permission_experiment/src/tune_four_label_classifiers.py`。

### 4.1 固定外层 test

脚本先复用与旧基线完全相同的外层划分，再仅把外层 train 送入 inner CV（`tune_four_label_classifiers.py:638-665`）。参数冻结后，才在完整 outer train 上重训并评估 outer test。

### 4.2 inner CV

- participant 主协议：3 折 `GroupKFold`，group 为 `participant_id`（`tune_four_label_classifiers.py:134-149`）；
- row 补充协议：3 折按行的 `StratifiedKFold`（`:150-156`）；
- 每 fold 的预处理只在 fit 部分拟合，再变换 validation（`:220-222`）；
- out-of-fold 预测必须覆盖 outer train 的每一行（`:297-302`）。

canonical 2026-08-09 运行实际搜索了以下显式网格，而不是依赖以后可能改变的默认值：

| 项目 | 网格 |
|---|---|
| 所有 LR 的 `C` | `{0.1, 0.3, 1, 3, 10}` |
| `class_weight` | `{balanced, None}` |
| Ordinal 决策阈值 | `{0.35, 0.40, 0.45, 0.50, 0.55, 0.60, 0.65}` |
| Factored access/persistence 阈值 | 各自 `{0.40, 0.50, 0.60}` |

对应每个 split：Flat 10 个候选；Ordinal 10×7=70 个候选；Factored 为 10×10×3×3=900 个组合。候选由 inner out-of-fold 预测比较，不能用 outer test 排序。

### 4.3 排序与冻结

候选按以下字典序选择（`tune_four_label_classifiers.py:368-385`）：

1. macro-F1：高者优先；
2. QWK：高者优先；
3. accuracy：高者优先；
4. over-sharing rate：低者优先；
5. persistent over-allow rate：低者优先。

选定参数后，预处理器只在完整 outer train 上 `fit_transform`，outer test 只做 `transform`（`:393-405`）。默认基线固定为 `C=1`、`class_weight=balanced`，Ordinal 与 Factored 的默认阈值均为 0.5（`:406-448`）。

### 4.4 代码快照与运行产物

canonical 产物位于 `classification_experiments/artifacts/nested_tuning_20260809/`，每个 split 至少应保留：

- `run_config.json`：数据/脚本哈希、划分、fold、网格、环境版本；
- `cv_results.csv`：仅 outer-train OOF 候选结果及排序；
- `selected_hyperparameters.json`：冻结参数与选择规则；
- `test_metrics.csv`、`test_predictions.csv`：冻结后的 outer-test 结果；
- confusion matrix、classification report 与 convergence diagnostics；
- participant 主协议的 `participant_bootstrap_deltas.csv`。

运行时顶层调参脚本的精确快照保存在：

`classification_experiments/artifacts/nested_tuning_20260809/source/tune_four_label_classifiers_run_snapshot.py`

其 SHA-256 为 `A476B363255808D6EA82F1F4C5FA18FE51E65D9BFD196323B8B603A34EE1AB2C`，与两个 `run_config.json:4-5` 记录一致。当前主脚本 SHA-256 为 `AFA95890CE44E485B38A998BF53C994FDD76D0B3A579892DE2BAE32732D7E51B`；它在运行后新增了 fold/单类 preflight 和拒绝向非空目录混写的保护，不改变候选搜索、拟合与排序算法。复核历史结果时用 snapshot；发起新实验时用当前加固脚本。

## 5. 指标定义与方向

指标实现位于 `run_four_label_benchmark.py:181-213`。

| 指标 | 定义/作用 | 方向 |
|---|---|---|
| accuracy | 全部逐行预测的正确率 | 越高越好 |
| macro-F1 | 四类 F1 的不加权平均；避免多数类完全主导 | **越高越好，主选择指标** |
| quadratic weighted kappa（QWK） | 考虑 0-3 有序距离的一致性 | 越高越好 |
| over-sharing rate | `true∈{0,1}` 中被预测为 `pred∈{2,3}` 的比例 | **越低越好** |
| persistent over-allow rate | `true!=3` 中被预测为 `pred=3` 的比例 | **越低越好** |

风险率必须连同分子和分母报告。`participant_bootstrap_deltas.csv` 中的 delta 定义为 `tuned - baseline`：前三项指标正值代表改善；两个风险率负值才代表改善。禁止把所有正 delta 统一解释为“更好”。

安全指标目前只作为 macro-F1 平局后的 tie-break，并非硬约束。因此“macro-F1 提升”可能伴随过度共享风险恶化；必须并列报告，不能只呈现主指标。

## 6. 统计不确定性

participant test 有 41 名参与者、3,323 行。行内共享同一个人和相同场景结构，不能把 3,323 行当作 3,323 个独立统计单位。

当前调参运行对 `tuned - baseline` 做 2,000 次 participant-cluster bootstrap：每次有放回抽取 41 个参与者，并带入被抽中参与者的全部行（`tune_four_label_classifiers.py:546-591`）。因此：

- CI 的单位是 participant，不是 row；
- CI 反映固定 seed 42 外层 test 上参与者构成的不确定性；
- 只有一个固定外层划分，不能据此声称跨随机划分稳定；
- CI 跨过 0 时，不应宣称稳定改善；即使不跨 0，也仍受历史 test-touched 和固定场景目录限制。

row split 不生成主推断性 bootstrap 结论。

## 7. Oracle/特权特征风险

当前特征包含 `necessity_status`。该字段不是由参与者标签直接计算，但它由 `queries.json` 中作者标注的必要数据与显式错误数据构造（`ai_agent_permission_experiment/src/build_dataset.py:70-90`），而上游数据说明把 query 元数据描述为带 ground truth 的场景（`ai_agent_permission_experiment/external/ai-agent-permissions/data/README.md:44-53`）。它与“是否应允许访问”高度接近，并在相同 query/context 跨参与者重复时保持稳定。

只有当部署系统在预测前确实能从可信 planner、tool schema 或人工标注中获得同等信息时，使用它才是可部署的。否则它属于 oracle-like/privileged feature，会让离线结果偏乐观。`domain` 若在线上同样依赖人工标注，也应按相同原则审计。

后续实验必须在文档中写明 feature regime，建议至少区分：

| regime | 说明 | 可支持的结论 |
|---|---|---|
| `annotated_full` | 保留当前全部特征，包括 `necessity_status` | 仅限“已有 query 标注可用”的条件结果；用于与旧基线逐值比较 |
| `deployment_safe` | 移除部署时不可获得的 `necessity_status`，必要时也移除人工 domain | 更接近真实上线条件，应作为未来部署主结果 |
| `query_heldout` | 在 deployment-safe 特征基础上按 query/context 分组外层评估 | 新场景泛化；需新增独立协议，不能与 participant split 混称 |

最少应做 `annotated_full` 对 `deployment_safe` 的成对消融，并保持外层划分、标签和其余预处理不变。若差距很大，应把它解释为对 privileged metadata 的依赖，而不是模型本身的泛化能力。

## 8. 安全复现命令

以下命令从 `Week67` 根目录运行，先验证输入哈希，再写到从未存在的新目录。不要把 `--out` 指向 `results/`、`reproduced_baseline/` 或 `nested_tuning_20260809/`。

### 8.1 逐值复现未调参基线

`run_four_label_benchmark.py` 本身会在目标 split 目录写文件但不会全面保护旧文件，因此外层目录必须由调用者先检查。

```powershell
$BaselineTag = Get-Date -Format 'yyyyMMdd_HHmmss'
$BaselineOut = Join-Path 'classification_experiments\artifacts' "manual_baseline_$BaselineTag"
$BenchmarkData = 'ai_agent_permission_experiment\data\processed\four_label_dataset.csv'
$ExpectedBenchmarkHash = '4A6F61191318EAA79BA2FAC1AB80E6FB850E099F1F0178EEF2F53B3B527FE463'

if (Test-Path $BaselineOut) {
  throw "Refuse to reuse existing output directory: $BaselineOut"
}
if ((Get-FileHash -Algorithm SHA256 $BenchmarkData).Hash -ne $ExpectedBenchmarkHash) {
  throw 'Input dataset hash mismatch'
}

python ai_agent_permission_experiment\src\run_four_label_benchmark.py `
  --data $BenchmarkData --split participant_heldout --out $BaselineOut
python ai_agent_permission_experiment\src\run_four_label_benchmark.py `
  --data $BenchmarkData --split row_stratified --out $BaselineOut
```

### 8.2 发起新的无直接 test 选参运行

显式传入 canonical 网格，避免当前或未来默认网格变化造成静默差异。

```powershell
$NestedTag = Get-Date -Format 'yyyyMMdd_HHmmss'
$NestedOut = Join-Path 'classification_experiments\artifacts' "manual_nested_$NestedTag"
$NestedData = 'ai_agent_permission_experiment\data\processed\four_label_dataset.csv'
$ExpectedNestedHash = '4A6F61191318EAA79BA2FAC1AB80E6FB850E099F1F0178EEF2F53B3B527FE463'

if (Test-Path $NestedOut) {
  throw "Refuse to reuse existing output directory: $NestedOut"
}
if ((Get-FileHash -Algorithm SHA256 $NestedData).Hash -ne $ExpectedNestedHash) {
  throw 'Input dataset hash mismatch'
}

python ai_agent_permission_experiment\src\tune_four_label_classifiers.py `
  --data $NestedData `
  --out $NestedOut `
  --splits participant_heldout row_stratified `
  --inner-folds 3 `
  --random-state 20260809 `
  --bootstrap-samples 2000 `
  --c-values 0.1 0.3 1 3 10 `
  --ordinal-thresholds 0.35 0.40 0.45 0.50 0.55 0.60 0.65 `
  --factored-thresholds 0.40 0.50 0.60

Get-Content -Raw (Join-Path $NestedOut 'participant_heldout\run_config.json')
Import-Csv (Join-Path $NestedOut 'participant_heldout\test_metrics.csv')
Import-Csv (Join-Path $NestedOut 'participant_heldout\convergence_diagnostics.csv') |
  Where-Object { $_.converged -ne 'True' }
```

最后一条命令应无输出；若出现未收敛记录，不能静默接受，应提高 `max_iter`、检查数据/特征，并用新目录重新运行。

如需对 canonical 2026-08-09 运行做代码取证，应先核对 snapshot 哈希，并用 snapshot 而非当前主脚本；新运行则使用当前主脚本的保护性检查。无论使用哪一个版本，都必须保存新的 `run_config.json`，不得混入旧目录。

## 9. 新增模型时的强制清单

每个后续 basic classifier 的 Markdown 记录必须包含：

1. 数据 CSV 的完整路径与 SHA-256；
2. 标签映射、特征字段和 feature regime；
3. 外层 split、seed、行数、参与者数及参与者/query/context overlap；
4. inner CV 的 group 单位、fold 数和预处理拟合位置；
5. 完整搜索空间、选择指标、阈值与 tie-break；
6. 参数冻结前没有读取 outer-test 指标的声明；
7. accuracy、macro-F1、QWK、两个风险率、逐类结果与 confusion matrix；
8. participant 聚类的不确定性估计；
9. convergence、warning 和失败运行；
10. 唯一的新产物目录、代码哈希和环境版本。

如果模型方案是在查看当前固定 test 后新增的，应明确标记为“基于历史 benchmark 迭代”，并优先用新的 outer participant folds 做比较；不能通过不断复用 seed 42 test 来宣称最终最佳模型。
