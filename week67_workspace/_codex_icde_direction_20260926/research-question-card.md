# ICDE 2027 方向判断与实验卡

日期：2026-09-26。性质：基于现有证据的方向建议，不是已验证的新方法或已获批执行的实验计划。

## 1. 推荐方向

以用户偏好驱动的运行时数据授权管理为主线，围绕有限反馈、询问、授权复用和失效展开；系统机制承载贡献，用户偏好与任务成本验证价值。RL 保留为可选对照，不作为投稿前置条件。用户已确认 LLM security 尚未开始，因此不建议在投稿前另起 security LLM 微调或完整防御框架。

候选问题：在明确的授权边界内，利用有限用户历史与反馈，能否比强 ICL 和明确作用域/撤销规则的缓存策略，更好地决定何时询问、何时复用，以维持任务完成率并降低错误授权及不必要打扰？

这一方向仍需验证新颖性。“ICL + 授权核 + 缓存”“增加置信度阈值”“四分类替换二分类”都不足以自动构成研究贡献。候选增量应落实为可检验的权限证据复用/失效决策，且必须超过强规则与检索历史基线。不要把标准的作用域检查或撤销操作本身称为新技术。

## 2. Research Question Card

- **Question:** 在同一授权执行层和相同反馈预算下，个性化历史使用与授权复用策略，能否在错误授权风险和任务完成率受控时降低实际询问负担？
- **Type:** exploratory，随后冻结协议做 confirmatory evaluation。
- **Hypothesis:** 用户历史有助于在相似但不完全相同的任务间作决策；显式管理证据的上下文适用性和授权生命周期，可能比静态 ICL 或纯缓存获得更好的风险—询问—任务完成权衡。尚未得到验证。
- **Why it matters:** agent 跨工具/对象使用个人数据时，自动化、用户控制和授权持续时间相互制约；“预测正确”尚未回答“可否执行、能否复用、何时重新询问”。
- **Current evidence:** 真人四分类 ICL 已跑通，但拒绝类错误明显；现有授权核与生命周期原型可复用；当前小型多步任务中规则与学习器同达上限。
- **Missing evidence:** 公平的真人配对基线；实际询问与授权复用的端到端收益；强规则对照；作用域变化和撤销测试；独立的攻击效果验证。
- **Support:** 在冻结的风险约束和完成率非劣界内，较最强基线降低询问，且用户/任务聚类置信区间支持该收益；或在同等询问预算下明显降低错误授权且不损害任务效用。效果阈值应在 dev 上结合使用需求预定。
- **Falsification:** 优势仅来自更多标签、更丰富输入或共享安全层；只改善合成数据；强规则/检索 ICL 已达到相同边界；全部策略在任务中封顶；收益以违背“下次再问”要求或拒绝更多正常任务为代价。
- **Minimal next action:** 先完成同协议 human 0/4-shot + 检索 ICL/简单监督基线，再以现有授权内核做复用/上下文变化/撤销三组配对任务。
- **Decision:** 进行两周方向验证；不启动新的大规模 RL 微调。

## 3. 当前证据与允许的结论

### ER-20260926-human-icl-01

- Allowed: 固定协议下，四分类真人 ICL 对拒绝和持久化仍有明显错误。
- Forbidden: 已证明四个历史示例带来真人收益；已经解决安全权限管理。配对真人 0-shot 尚缺。

## 4. 现有资产与应收窄的系统范围

已有 Scope、AuthorizationService、ReferenceMonitor、一次/持续授权、expiry、reserve/settle、scope matching 和审计等原型。优先复用，不大幅重构。

建议逻辑流程：当前请求及可信历史 → 偏好/询问/复用决策 → 明确授权记录及生命周期检查 → 实际数据/工具操作 → 用户反馈与审计。

权限预测、权限签发、权限执行应在评估中分开。模型预测“用户可能同意”不等于已经获得用户授权。可执行权限来自可信确认或事先明确授予的委托规则；偏好预测不得绕过硬授权边界。反过来，形式上满足授权内核，也不代表准确符合用户偏好。

原型是同进程执行语义验证，不等于 hostile runtime 隔离或完整防注入保证。现有 public31 控制器输入不编码自由文本，仅在该输入上做结构化扰动不能声称评估了 LLM prompt injection。

## 5. 指标：先写清分母，再比较

设 y 为参考偏好，a 为模型建议；运行时另记实际执行、询问和拦截事件。保留原始数量 n/N。

| 指标 | 定义与用途 | 注意事项 |
|---|---|---|
| False allow（真人离线） | #预测 allow 且 y=deny / #y=deny | 衡量拒绝偏好的漏保护；与现有 42.48% 定义一致。 |
| 自动允许风险 | #自动允许但违反参考拒绝偏好 / #自动允许 | 反映一次自动允许有多大风险；同时报分母、允许覆盖率、置信区间。参考偏好必须有独立来源。 |
| 预测/自动化 coverage | #无需当前用户反馈即可决策 / #合格请求 | 区分自动 allow、自动 deny 与 ask；deny-all 不能被包装为高效自动化。 |
| 实际询问负担 | 询问总数/全部任务；成功任务上的询问数另报 | 还要计被拒绝/失败任务中的询问，避免幸存者偏差。一个 query 可能涉及多个权限标签。 |
| 再次询问偏好遵从 | 在用户已要求 ask-next-time 且再次出现对应请求时，正确重新询问的比例 | 少问不能以违反用户要求为代价；ask-next-time 标签不等于本轮发生了询问。 |
| 错误永久允许 | #a=allow-persist 且 y≠allow-persist / #y≠allow-persist | 当前定义包含把一次允许升级为长期允许；另报预测持久允许中的错误比例。与 false allow 有交集，不相加。 |
| 持久授权后果 | 每条错误持久授权导致的后续错误执行次数；不适用/已撤销/过期授权复用率 | 必须实际走后续步骤，不能仅用四分类分数替代。 |
| 撤销生效 | 从可信撤销事件到禁止后续提交的延迟；撤销后提交数量/机会数 | 撤销后的正确处理不等于发现未观察到的心理偏好变化。 |
| 任务效用 | 合法可完成任务上的完成率；全任务结果分布；应拒绝任务上的正确安全终止率 | 不把合法拒绝全算失败，也不把拒绝算完成；两种任务单独列出。 |
| 硬权限违规 | 已提交的未授权 effect/受保护提交机会；按越界、过期、撤销后使用分项 | 被 monitor 拦下的提案另报。零违规来自公共 monitor 时应归于系统层。 |
| 攻击成功率 ASR | 恶意目标实际达成的攻击 episode / 有效攻击 episode | 不等于 false allow；同时给 clean task success 与 attacked task success。 |
| 偏好预测诊断 | 四类 macro-F1、per-class recall、joint accuracy、access/persistence 分解 | 主结论不能仅靠 accuracy；四类不天然等距，QWK 不宜作为核心。 |
| 成本与效率 | p50/p95 端到端延迟、每任务 token/API 成本、训练/维护成本、适应所需反馈 | 离线按用户批量预测成本不能直接当实时单次请求成本。 |

主图建议：横轴实际询问量（或明确注明的自动处理覆盖率），纵轴错误授权风险；在相同完成率要求下比较 Pareto 边界。另画历史预算学习曲线、授权复用错误随上下文变化的曲线和主要消融图。

目标可表述为：在错误授权风险不超过预先约定范围、合法完成率不低于基准非劣界、用户要求再次询问得到遵守的条件下，降低实际询问成本。阈值在 dev 选定；报告达不到约束的方法，不在 test 上调到“刚好好看”。不必将所有指标压成单一手工 reward。

统计单位优先为用户及独立任务模板，配对比较并给聚类区间；seed 是训练随机性的重复，episode 不是独立真人。零失败只能写 0/N；独立同分布试验下零事件的一侧 95% 上界为 1−0.05^(1/N)，相关场景不能直接套用独立假设。当前 LLM 自报 score 未校准，不能作真实概率；阈值策略需独立验证风险和 coverage。

## 6. 必须先解决的公平性

1. 统一用户/query bundle 划分、历史可见性、标签预算及运行时输入。当前 ICL 有原始文本和 profile，而旧 bandit 主要是结构化 features；旧表不能直接作为公平方法排名。
2. 同一用户的一个 query 内含多项权限，应整体留出，禁止部分标签泄漏到同 bundle 的其他预测中。4-shot 指 4 个 query，不是 4 个标签；同时报 query 数、判断数和用户交互轮次。
3. 0/1/2/4/8 历史预算按实际可用样本确定，不能为凑 8-shot 而重复示例或改变目标集合。所有方法共享同一历史，检索策略在同一已观察历史池中选择。
4. 如果询问后可见完整四类标签，增加简单在线监督学习；不能人为只给监督方法/其他 baseline 更少信息。
5. 模型/超参数/阈值选择与最终评估分开。已有结果已经被查看，不能事后重新命名为未触碰测试；冻结后续协议并透明说明既有模型筛选重叠。
6. 静态问卷随机顺序 replay 不是真实时间轨迹。模拟 drift、显式脚本撤销、真人 longitudinal study 应分别命名。
7. 同一个授权内核必须给所有策略用。另做执行层消融时保持上游预测不变，分别定位个性化贡献和 enforcement 贡献。

## 7. 两周最小方向验证

### 9/26—10/2：统一协议并补真人证据

- 补同一真人集合/同一 fold 的 0-shot；保留 4-shot；加入历史检索 ICL、简单监督/在线监督、现有 bandit 中有代表性者。
- 至少一个文献对齐强 baseline：原 ICL+CF 或 ARIEL 风格历史推断；若四类改造不完全等价，写清适配范围，并把原任务复现与新任务比较分开。
- 先做风险—coverage / 询问曲线、拒绝类诊断与历史预算对比，再决定是否扩展所有 folds；最终报告应覆盖示例/划分变异，不能挑最佳 fold。
- 不新增大规模 simulator 或 RL sweep。

### 10/3—10/10：现有内核上的配对运行时实验

三类场景：有效同范围授权复用；对象/工具/数据类型/目的改变；可信撤销后重复请求。补一次性授权消费和 expiry 等已有机制的必要边界检查。

最小方法组：每次询问；强规则（明确作用域 + TTL/expiry + 撤销 + 缓存）；强 ICL/检索历史接同一内核；候选个性化策略接同一内核。若研究 learned strategy 的增量，比较必须保持 enforcement 完全相同。

比较询问量、合法任务完成、错误复用、偏好违背与成本；冻结每组基准输入和场景选择，不按新方法好坏删场景。动态脚本只验证指定授权语义，不充当真实偏好变化证据。

### 第 14 天 decision gate

- **继续:** 相对最强规则/ICL，有稳定且有实际意义的风险—询问—效用改进，并能通过消融定位增益。
- **收窄:** 只有明确系统机制收益，学习增量不成立 → 去掉学习最优/必要的主张，重新审查机制本身是否有足够新颖性。
- **重新定位:** 规则完全封顶、仅 synthetic 变好、或仅靠放宽风险减少提示 → 停止扩大训练；重新设计能反映真实权衡的任务或调整论文目标。

RL 只有在自然的延迟后果（一次/持续授权影响后续任务、有限询问资源等）产生稳定跨步权衡，且强规则、检索 ICL、在线监督/短视策略无法解决时再进入关键路径。不能为让 RL 获胜而制造任意奖励延迟。小状态空间应比较 exact planning/DP 及其成本。

## 8. 尚未启动的 security 如何补

P0：验证作用域越界、撤销后重放、跨对象/工具误复用、一次授权升级持久授权；记录实际 effect 与阻止事件。强规则基线也有相同检查，不能仅击败无防护系统。

P1：若接入实际 LLM 处理不可信工具输出，加入明确的 prompt injection，例如伪造用户授权、要求扩大作用域或更换数据接收者。使用干净/攻击配对任务，攻击选择与恶意目标预先确定。测 targeted ASR、clean utility、attacked utility，输出不是按文字拒绝判断成功。

若只能完成结构化权限扰动，应把结论限定为 authorization robustness；不写“解决 LLM security”。更不需要先训练一个 security LLM。

## 9. ICDE 定位、时间与文献边界

官方 Research Round 2 截止 **2026-11-11 17:00 Pacific / 多伦多 20:00**，不是 AoE。9/26 起约 46 天。Research 包含 regular 与 EAB，正文最多 12 页（参考文献及 AI acknowledgement 另计），无 revision 选项。以提交时官方信息为准。

建议：10/10前完成方向判别；10/11—10/23冻结并完成主实验、安全与消融；10/24—11/1形成完整初稿；11/2—11/8教授审阅及必要补证据；11/9—11/10完成提交检查。方法和相关工作可从第一周并行写，不等实验全部结束。

ICDE 匹配应落到数据访问管理：授权状态、上下文适用性、生命周期、执行语义、审计及效率。不能仅以增加模块图宣称数据库系统贡献。EAB 需要独立的新认识及充分复现证据，也不是弱方法结果的自动后备通道。
