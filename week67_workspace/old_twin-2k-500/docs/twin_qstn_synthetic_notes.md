# Twin-2K × Permission-Condition QSTN: Implementation Notes

## Scientific boundary

`(twin_id, policy_condition)` is a research-constructed synthetic agent.  A
Twin participant is not being asserted to have the selected permission policy,
and an answer generated by the system is not a new observation from that Twin
participant.  This module is for controlled population heterogeneity and RL
environment simulation.

## Inputs

- Twin table supplied locally as CSV or Parquet, with `pid` and
  `persona_summary` columns.
- Frozen QSTN V2 policy cards at
  `ai_agent_permission_experiment/qstn_simulator/config/empirical_profile_prompt_cards_v2.json`.
- Existing permission scenarios at
  `ai_agent_permission_experiment/qstn_simulator/outputs/questionnaire_items.csv`.

## Non-goals

- No training, prompt tuning, human-label fitting, or claims of external human
  validity.
- No automatic Twin dataset download and no default API execution.
- No changes to the empirical V1/V2 persona compiler or held-out calibration.

## Runtime design

- The compiler writes one row per `Twin × policy-condition` agent.
- The runner first writes a deterministic inference plan and a manifest.
- `--dry-run` is safe and credential-free; `--execute` uses an
  OpenAI-compatible endpoint, so it can also be configured for OpenRouter.
- Output prediction tables retain the raw answer and parsed four-label answer,
  but contain no human target label.

## Verification completed

- A two-row, fictional-only Twin-format fixture compiled into six agents:
  `2 Twin ids × 3 policy conditions`.
- QSTN offline dry-run rendered and validated all `6 × 2 = 12` prompts against
  the existing permission questionnaire.
- The verification made no model API request and did not download Twin-2K.
- A deliberately lowered request ceiling rejected a 12-call plan before any
  output/API operation, confirming the large-run guard is active.

## Archive decision

The project has decided not to use the Twin-2K × old policy-card cross-product
as the active QSTN persona. The implementation and its historical appraisal
notes are being moved together into `old_twin-2k-500/`, preserving relative
provenance while leaving the frozen profile-card V2 files in place.
