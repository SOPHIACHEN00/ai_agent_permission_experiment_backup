# Task Plan: S-QSTN RulePack v1.1 Planning and Implementation

## Goal

Define a reviewable v1.1 scope that adds current-turn uncertainty, prompt-burden metadata, and structured audit reason codes without introducing longitudinal state, numeric weights, or QSTN core changes.

## Phases

- [x] Phase 1: Confirm the v1.0 baseline and current questionnaire schema.
- [x] Phase 2: Freeze v1.1 scope, non-goals, and rule activation boundaries.
- [x] Phase 3: Design the v1.1 context schema, qualitative buckets, audit schema, and version tuple.
- [x] Phase 4: Define implementation files, tests, ablations, and acceptance criteria.
- [x] Phase 5: Present the plan for user approval and receive approval before implementation.
- [x] Phase 6: Reorganize versioned configuration assets into `config/v1.0/` and `config/v1.1/`.
- [x] Phase 7: Implement and verify v1.1 sidecar, compiler, runner integration, and tests.

## Key Questions

1. Which v1.1 fields are explicit public context and which must remain unknown rather than inferred?
2. Should uncertainty affect the respondent prompt, remain audit-only, or have a separately ablated qualitative modifier?
3. How can current-turn prompt burden be represented without claiming cross-turn fatigue or habituation?
4. Which source rules remain deferred to v2 longitudinal state or v3 human calibration?
5. What artifacts must be versioned so that v1.0 and v1.1 remain comparable?

## Decisions Made

- The user approved the three implementation decisions: `audit_compatible` default, sidecar context carrier, and exploratory mode restricted to synthetic/ablation use.
- The proposed v1.1 scope must preserve the v1.0 JSON semantics as a backward-compatible baseline condition.
- The recommended default is `audit_compatible`; any answer-affecting qualitative modifier must be an explicitly separated exploratory mode.
- The recommended context carrier is a versioned sidecar keyed by `questionnaire_item_id`, not a mutation of the v1.0 questionnaire CSV.
