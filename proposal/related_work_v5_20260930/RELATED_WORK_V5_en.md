# Related Work

Permission management for a personal assistant agent involves learning user preferences and controlling how tools access and transmit data. Existing work addresses permission prediction, dynamic least privilege, and training for privacy-aware behavior. Prediction concerns agreement with user preferences. Enforcement constrains access to granted permissions, while model training shapes access and disclosure behavior. We study how these capabilities work together over repeated interactions with the same user. Specifically, we examine changes to access scope and authorization duration under the same authorization enforcement constraints. We ask whether using ongoing user feedback to guide these changes improves the balance among task completion, unnecessary data exposure, and user interruptions.

## Permission Preference Prediction and Personalization

Personalized permission decisions have been studied in mobile applications. Liu et al. proposed a privacy assistant that recommends app permission settings from a small amount of user input. They evaluated the assistant on participants' own Android devices \citep{liu2016follow}.<!--ref:liu2016follow--><!--anchor:section:Abstract--> Wijesekera et al. used access context and past decisions to predict permission preferences, asking users to decide when predictions were uncertain \citep{wijesekera2017feasibility}.<!--ref:wijesekera2017feasibility--><!--anchor:section:Abstract--> Although focused on mobile applications, these studies account for individual preferences and context rather than applying the same fixed rules to every user.

Wu et al. studied data access preferences for personal assistant agents and built a permission prediction assistant using in-context learning (ICL) and collaborative filtering. They examined how user history and prediction confidence affected predictive performance. Their survey offered four response options, but the main prediction evaluation retained only the always-allow and never-allow responses as binary labels \citep{wu2026automating}.<!--ref:wu2026automating--><!--anchor:section:4.1.1,5.1,5.2.1--> We retain all four options to capture preferences about both the current request and whether the user wishes to be asked again. We distinguish this prediction task from permission control during task execution.

## Online Adaptation and Sequential Decision-Making

Prediction accuracy given an existing user history does not establish whether later feedback will improve subsequent decisions. Online updating is not exclusive to reinforcement learning (RL). Wijesekera et al. evaluated an incremental permission classifier that incorporated new feedback in chronological order \citep{wijesekera2017feasibility}.<!--ref:wijesekera2017feasibility--><!--anchor:section:VII-C--> Multi-armed bandit (MAB) models provide another approach to decisions based on incoming feedback. Thompson sampling, for example, updates reward estimates from feedback on selected actions and uses probabilistic sampling to balance exploration and exploitation \citep{russo2018tutorial}.<!--ref:russo2018tutorial--><!--anchor:section:2,3--> These methods allow us to study whether a policy adapts to an individual user as feedback accumulates. Such adaptation needs to be compared with a policy without updates under identical initial conditions.

Permission decisions can also change the authorization state available to later steps. Reusing a valid permission can avoid another interruption, whereas revoking it too early may require a new request. Basic MAB formulations do not explicitly model state transitions caused by actions. Value-based RL accounts for these transitions and future rewards when evaluating actions. Double DQN is one such method \citep{vanhasselt2016deep}.<!--ref:vanhasselt2016deep--><!--anchor:section:Background,Double Q-learning--> This distinction motivates comparing online decision policies with sequential permission control. It does not establish that RL will outperform simpler alternatives. Response prediction with ICL or classifiers, feedback adaptation with MAB, and task execution under sequential policies therefore require separate evaluation.

## Least Privilege and Authorization Management in Multi-Step Tasks

Learning user preferences must be supported by mechanisms that enforce permissions during execution. MiniScope derives required permissions from a task execution plan and a permission hierarchy. It constrains tool calls through user approval and an independent checker, with support for one-time, session-level, and persistent authorizations \citep{zhu2025miniscope}.<!--ref:zhu2025miniscope--><!--anchor:section:IV-B,IV-C--> Progent restricts tool calls through symbolic rules over tools and their arguments. It deterministically checks whether a policy update permits additional operations. Permission narrowing can take effect automatically, while expansion is handled by a configurable approval mechanism \citep{shi2026progent}.<!--ref:shi2026progent--><!--anchor:section:4.3,7--> MiniScope links task requirements to authorization granularity, whereas Progent constrains policy updates. Both support more than static, tool-level allow or deny decisions.

Authorization management also affects user interruptions. GAAP stores user permissions for data disclosure and constrains subsequent propagation through information-flow checks and persistent disclosure records. In experiments with consecutive tasks, retaining permission records reduced user interactions compared with clearing them after every task \citep{stanley2026gaap}.<!--ref:stanley2026gaap--><!--anchor:section:3.3,4.3-4.5,6.5--> Since authorization reuse itself affects interaction costs, fewer interruptions alone do not establish a benefit from preference learning.

Permission to read data does not automatically authorize disclosure to other tools. CaMeL separates control flow from data flow and attaches metadata about sources and permitted recipients to data. It uses these annotations to check information flows in subsequent tool calls \citep{debenedetti2025camel}.<!--ref:debenedetti2025camel--><!--anchor:section:4.2,4.3--> In our travel-planning example, permission to read a confirmation email does not imply permission to copy the entire email into a calendar. The times and locations needed for the calendar entry should be separated from unrelated email content. Managing access scope thus concerns both which data can be read and where those data can subsequently be sent.

## Learning Privacy-Aware Behavior and Evaluating Execution

Learning methods have been used to reduce unnecessary disclosure and excessive privilege use by agents. CI-RL trains language models with RL to distinguish information needed for a task from information that should not be disclosed \citep{lan2025contextual}.<!--ref:lan2025contextual--><!--anchor:section:Abstract--> ToolPrivBench examines whether agents choose higher-privilege tools when lower-privilege tools suffice, or escalate privileges prematurely after temporary failures. Its authors use supervised fine-tuning and RL to improve tool selection behavior \citep{yang2026lower}.<!--ref:yang2026lower--><!--anchor:section:3,5.3--> Tu and Tu combine task-specific permission requirements, execution auditing, and RL post-training in executable terminal and MCP environments to reduce excessive privilege use \citep{tu2026task}.<!--ref:tu2026task--><!--anchor:section:III-A,III-B,III-D--> Our learning target is a separate permission decision policy, rather than the task language model itself. We examine how this policy uses ongoing feedback from the same user to manage access scope and authorization duration.

Evaluating permission decisions requires separating model responses from actual execution. PrivacyLens reports discrepancies between answers to privacy-norm questions and disclosure behavior when models carry out user instructions. It therefore evaluates agent actions as well \citep{shao2024privacylens}.<!--ref:shao2024privacylens--><!--anchor:section:Abstract--> ToolEmu uses language models to emulate tool execution and assesses agent risks from execution traces \citep{ruan2024identifying}.<!--ref:ruan2024identifying--><!--anchor:section:Abstract--> These evaluations complement permission response prediction. Whether responses match user preferences and what information the agent actually accesses or discloses need to be evaluated separately.
