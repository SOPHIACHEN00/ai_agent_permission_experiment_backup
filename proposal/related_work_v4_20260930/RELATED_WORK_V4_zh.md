# Related Work

个人助理的权限管理连接了用户偏好学习与运行时访问控制：系统既需要理解用户愿意授予什么权限，也需要限制这些权限在任务执行中的使用。本文关注二者之间的决策过程，即在用户实际授权的边界内，持续利用同一用户的反馈调整访问范围与授权期限，能否改善任务完成、不必要数据暴露和用户打扰之间的权衡。

## 权限偏好的预测与个性化

利用用户历史辅助权限决策，在移动隐私研究中已有基础。Liu 等提出个性化隐私助理，通过少量用户输入推荐移动应用的权限设置，并在用户自己的 Android 设备上进行评估。[Liu et al., 2016](https://www.usenix.org/conference/soups2016/technical-sessions/presentation/liu)<!--ref:R2--><!--anchor:section:Abstract--> Wijesekera 等进一步结合访问上下文与既往决策预测用户偏好，在预测不确定时请求确认，并研究根据新反馈增量更新模型。[Wijesekera et al., 2017](https://www.ieee-security.org/TC/SP2017/papers/278.pdf)<!--ref:R3--><!--anchor:page:1,12--> 这些工作将个性化权限管理与减少人工决策负担联系起来，也为区分已有历史的预测价值和新增反馈的适应价值提供了基础。

Wu 等的 *Towards Automating Data Access Permissions in AI Agents* 是与本文直接相关的研究。该工作通过用户研究分析 Agent 数据访问偏好，结合上下文学习与协同过滤建立权限预测助手，并考察历史记录和预测置信度对预测质量的影响。作者将研究重点放在偏好理解与预测，把可靠的运行时执行作为互补问题。其问卷提供四种回答，但主要预测实验只使用“始终允许”和“永不允许”，未纳入两类“下次再问”的回答。[Wu et al., 2026](https://homes.cs.washington.edu/~franzi/pdf/wu-agentperms-sp26.pdf)<!--ref:R1--><!--anchor:section:3.1,5.1-5.2--> 本文保留四类回答，因为当前是否允许访问与以后是否再次确认，会影响不同的权限决策。在此基础上，本文分别考察给定历史下的回答预测，以及从相同初始条件出发、吸收同一用户的新反馈后获得的改进，不以跨用户泛化作为研究目标。

## 多步任务中的最小权限与授权管理

用户愿意授予某项权限，并不意味着任务的每个阶段都需要使用它。MiniScope 将最小权限原则用于工具型 Agent：它根据执行计划和权限层级求解所需权限，通过用户确认与独立检查器约束调用，并支持一次性、会话级和持续授权。该预印本还通过三个月的模拟交互分析确认负担。作者同时指出，进一步细化到具体资源可能增加用户负担，而利用偏好预测减少确认又受到预测可靠性的限制。[Zhu et al., 2025](https://arxiv.org/html/2512.11147v1)<!--ref:N1--><!--anchor:section:IV-B,IV-C,VI-D,VII-B,VII-C--> 这说明，权限粒度和授权期限需要结合任务需求与交互成本来选择，单纯增加授权选项还不足以确定适合某位用户的策略。

动态调整权限还需要防止策略更新绕过原有授权边界。Progent 使用工具及其参数上的符号规则限制调用，并确定性地检查一次更新是否引入新的可执行操作。在其修订版中，权限收窄可以自动生效，权限扩张则交由可配置的审批机制处理。[Shi et al., 2026, v3](https://arxiv.org/html/2504.11703v3)<!--ref:R5--><!--anchor:section:2.2,4.3,5--> 这种机制规定了权限如何安全更新；在这些约束下，何时收窄、保留多久以及何时重新询问，仍是需要比较不同策略的决策问题。本文保持授权执行约束一致，考察这些选择在后续步骤中产生的影响。

已有授权的复用本身就能够减少询问，因此需要将其与偏好学习的收益区分。GAAP 保存用户的数据披露许可，并结合信息流检查和持久披露记录限制后续数据传播。其预印本中的连续任务实验表明，相比每个任务后清空许可记录，保留记录能够减少用户交互。[Stanley et al., 2026, v1](https://arxiv.org/pdf/2604.19657v1)<!--ref:N2--><!--anchor:section:3.3,4.3-4.5,6.5--> 这一结果为本文提供了直接的比较依据：持续适应的价值应相对于能够记忆和复用授权的规则策略来判断。否则，询问次数下降可能只来自保存了先前许可，而非学会了更合适的访问范围或授权期限。

对权限的管理还需区分读取与后续披露。CaMeL 将控制流与数据流分离，并为数据附加来源和允许接收方等标记，以检查信息能否传递给后续工具。[Debenedetti et al., 2025](https://arxiv.org/html/2503.18813v1)<!--ref:R6--><!--anchor:section:4.2-4.3--> 这类信息流机制处理的是数据在获准读取后如何继续传播的问题。例如，读取确认邮件和把邮件内容写入日历涉及不同的访问与披露条件。本文将这些条件视为权限策略必须遵守的执行约束，预测结果仅用于辅助请求与授权安排，不产生新的用户授权。

## 隐私行为学习与执行层评价

Agent 隐私保护也可以通过改变数据表示或模型行为实现。PrivacyAsst 提出加密与混洗方案，保护交给模型和工具处理的私密内容。[Zhang et al., 2024](https://doi.org/10.1109/TDSC.2024.3372777)<!--ref:S225--><!--anchor:section:3-5--> CI-RL 则通过强化学习训练语言模型，使其在完成任务时区分需要提供的信息与不应披露的信息。[Lan et al., 2025](https://proceedings.neurips.cc/paper_files/paper/2025/hash/968591afcfe4ba889eccffb6a4ca2d45-Abstract-Conference.html)<!--ref:R8--><!--anchor:section:Abstract--> 前者关注数据处理过程中的保密，后者学习符合上下文的披露行为。本文选择的学习对象是独立的权限决策策略，重点在于同一用户的反馈如何影响访问请求、授权复用和收回时机，而非对任务语言模型进行隐私行为后训练。

最小权限行为本身也已有学习方法。ToolPrivBench 在低权限工具足以完成任务的条件下，研究 Agent 是否仍选择高权限工具，或在暂时失败后过早扩权，并结合监督微调与强化学习改善这些行为。[Yang et al., 2026，预印本](https://arxiv.org/html/2606.20023v1)<!--ref:R10--><!--anchor:section:3,5.3--> Tu 与 Tu 则在可执行的终端和 MCP 环境中，以任务所需的权限范围为依据，通过执行审计和强化学习后训练减少过度权限使用。[Tu & Tu, 2026，预印本](https://arxiv.org/html/2608.18351v1)<!--ref:R11--><!--anchor:section:III-A,III-B,III-D--> 这些工作已经把完成任务和减少过度权限使用共同纳入训练。本文关注同一用户持续提供的权限反馈，以及保留或收回授权对后续步骤的影响。在这一交互设定下，序贯策略还需要处理一个问题：当前减少访问所带来的收益，是否值得之后可能增加的询问或任务中断。

上述比较需要落实到 Agent 的执行行为。PrivacyLens 发现，模型对隐私规范问题的回答与执行用户指令时的实际披露行为可能不一致，因而将评价延伸到 Agent 动作。[Shao et al., 2024](https://proceedings.neurips.cc/paper_files/paper/2024/hash/a2a7e58309d5190082390ff10ff3b2b8-Abstract-Datasets_and_Benchmarks_Track.html)<!--ref:R7--><!--anchor:section:Abstract--> ToolEmu 则利用模拟工具环境检查执行轨迹的风险与任务表现，为受控环境中的 Agent 评价提供了方法基础。[Ruan et al., 2024](https://arxiv.org/abs/2309.15817)<!--ref:S150--><!--anchor:section:Abstract--> 因此，权限回答的一致性与执行效果需要分别衡量：读取阶段考察是否访问无关数据，写入或发送阶段考察是否包含多余信息，授权持续期间则考察不再需要的数据是否仍然可访问。最后一种情况反映的是潜在暴露，不能计作已经发生的披露；这些指标也需要与任务完成情况和用户确认次数共同解释。
