# Related Work

本文关注同一用户持续交互中的权限管理，将权限偏好学习与执行阶段的访问控制联系起来，考察任务完成、用户打扰和不必要数据暴露之间的权衡。相关工作的一个核心区别在于，其处理的是用户愿意授予哪些权限，还是 Agent 实际需要使用哪些信息。前者提供个性化决策依据，后者要求进一步考察访问决策在任务执行中的后果。

## 个性化权限决策

移动应用中的权限研究已将用户历史与访问上下文用于个性化决策。Liu 等通过个性化隐私助理向用户推荐权限设置，并在真实 Android 设备上评价其使用情况。Wijesekera 等则进一步考虑访问上下文的变化，利用用户既往决策推断权限偏好，在不确定时请求用户确认，并讨论随反馈增量更新模型。[Liu 等，2016](https://www.usenix.org/conference/soups2016/technical-sessions/presentation/liu)<!--ref:R2--><!--anchor:section:Abstract-->；[Wijesekera 等，2017](https://www.ieee-security.org/TC/SP2017/papers/278.pdf)<!--ref:R3--><!--anchor:page:1,12--> 这些工作将权限管理从用户逐项配置，转向借助历史与上下文辅助决策，也确立了个性化判断与用户确认之间的联系。

在 Agent 场景中，Wu 等的 *Towards Automating Data Access Permissions in AI Agents* 是与本文最直接相关的工作。该研究通过用户研究刻画数据访问偏好，并结合上下文学习与协同过滤预测权限回答。其问卷收集了四种回答，但主要预测评估采用“始终允许”和“永不允许”两类标签。[Wu 等，S&P 2026](https://arxiv.org/html/2511.17959v1)<!--ref:R1--><!--anchor:section:V--> 对持续交互而言，“此次允许但下次再问”与“持续允许”虽然都接受当前访问，却表达了不同的后续确认要求。因此，本文在建模中保留四类回答，并将既有历史下的偏好预测与新增反馈带来的适应价值分开考察。

## 从隐私行为到运行时访问约束

用户愿意授权什么，并不能直接回答 Agent 在任务中实际披露了什么。PrivacyLens 将隐私情境扩展为 Agent 轨迹，发现模型对信息共享适当性的回答与其实际动作可能不一致，并结合任务帮助程度评价泄漏。[Shao 等，2024](https://proceedings.neurips.cc/paper_files/paper/2024/hash/a2a7e58309d5190082390ff10ff3b2b8-Abstract-Datasets_and_Benchmarks_Track.html)<!--ref:R7--><!--anchor:section:5.1-5.2--> 虽然这种隐私规范判断不同于用户权限回答预测，它说明了判断层评价与动作层评价不能相互替代。对于本文的权限管理问题，这意味着偏好一致性之外，还需要观察授权如何被使用。较低暴露量也需要与任务完成情况共同报告，以避免把拒绝执行或任务失败当作保护效果。

围绕实际信息披露，已有方法尝试通过学习改善 Agent 的隐私行为。CI-RL 将上下文完整性推理与强化学习结合，训练语言模型在完成任务时选择适当披露的信息。CDI 则将干预位置放在执行过程中，由独立指导模型提供上下文相关的隐私建议，并利用失败轨迹优化该模型。[Lan 等，2025](https://proceedings.neurips.cc/paper_files/paper/2025/hash/968591afcfe4ba889eccffb6a4ca2d45-Abstract-Conference.html)<!--ref:R8--><!--anchor:section:3-->；[Wen 等，2026](https://proceedings.mlr.press/v306/wen26k.html)<!--ref:R9--><!--anchor:section:Abstract--> 两者分别改变任务模型的披露行为与外部模型的指导行为。本文选择的学习对象则是独立权限控制器：任务语言模型提出工具调用，控制器根据反馈与授权状态辅助决定询问、复用或调整权限。其决策对象是授权操作及其范围和有效期。

在权限选择层面，最小权限学习进一步关注完成任务是否使用了超出需要的访问能力。ToolPrivBench 考察低权限工具足以完成任务时的高权限选择，以及临时工具失败后的不必要扩权，并研究权限感知的后训练。Tu 与 Tu 则在可执行的终端和 MCP 环境中，将任务相对的过量权限纳入强化学习目标。[Yang 等，2026，预印本](https://arxiv.org/abs/2606.20023)<!--ref:R10--><!--anchor:section:3-->；[Tu 与 Tu，2026，预印本](https://arxiv.org/abs/2608.18351)<!--ref:R11--><!--anchor:section:III-IV--> 前者侧重可替代工具之间的权限选择，后者将访问能力的使用放入执行轨迹中评价。这类研究把任务完成与权限适度作为不同的评价对象。权限学习与执行检查也处理不同的问题：前者改变策略的选择倾向，后者决定一次具体调用能否发生。

运行时访问控制通过显式规则决定调用能否执行。Progent 以工具名称和参数上的符号规则约束调用，由 LLM 生成和更新策略，并通过确定性检查区分权限收窄与扩张：收窄可自动应用，扩张需要审批。[Shi 等，Progent v3，2026，预印本](https://arxiv.org/html/2504.11703v3)<!--ref:R5--><!--anchor:section:2.2--> 这一机制将策略调整与执行许可分开，说明动态权限管理可以在明确的执行边界内进行。本文同样保留这种职责分离：学习组件的预测不直接构成授权，工具调用仍需通过实际授权记录的检查。由此，学习策略带来的询问和暴露变化，应在保持执行约束一致的条件下评价。

调用级授权检查还需要与信息流保护区分。CaMeL 分离控制流与数据流，并为数据附加描述允许读取者及来源的 capability，以约束不被允许的信息传播。[Debenedetti 等，2025，CaMeL 原稿](https://arxiv.org/html/2503.18813v1)<!--ref:R6--><!--anchor:section:4.2-4.3--> 与围绕工具名称和参数判断调用是否获准的机制相比，这类保护进一步关注数据在读取之后如何被使用和传递。获准读取某项信息，并不自动意味着可以将其发送给其他接收者；同样，工具调用通过权限检查，也不足以单独证明其中携带的信息都适合披露。
