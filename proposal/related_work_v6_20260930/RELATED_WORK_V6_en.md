# Related Work

Personal assistant agents need to account for users' preferences while keeping data access and disclosure within granted permissions. Relevant research addresses permission preference prediction, online adaptation, runtime authorization, and privacy-aware training and evaluation.

## Permission Preference Prediction and Personalization

Research on mobile applications provides a starting point for learning individual permission preferences. Liu et al. developed a privacy assistant that recommended app permission settings from a small amount of user input. They evaluated it on participants' own Android devices \citep{liu2016follow}.<!--ref:liu2016follow--><!--anchor:section:Abstract--> Wijesekera et al. used access context and past decisions to predict permission preferences, consulting users when predictions were uncertain \citep{wijesekera2017feasibility}.<!--ref:wijesekera2017feasibility--><!--anchor:section:Abstract--> These studies connect permission decisions to individual input and access context, rather than relying on the same fixed rules for every user.

Wu et al. studied permission preferences in personal assistant agents. They built a permission prediction assistant using in-context learning (ICL) and collaborative filtering. Their evaluation examined how user history and prediction confidence affected performance. The survey offered four response options, but the main prediction evaluation retained only always-allow and never-allow responses as binary labels \citep{wu2026automating}.<!--ref:wu2026automating--><!--anchor:section:4.1.1,5.1,5.2.1--> We retain all four options to distinguish the current access decision from the user's preference about being asked again.

## Online Adaptation and Sequential Decision-Making

Accurate predictions from an existing user history do not establish that a model will improve as new feedback arrives. Wijesekera et al. examined adaptation with an incremental permission classifier that incorporated new feedback chronologically \citep{wijesekera2017feasibility}.<!--ref:wijesekera2017feasibility--><!--anchor:section:VII-C--> Multi-armed bandit (MAB) methods offer another way to learn from incoming feedback. Thompson sampling, for example, updates estimates of action rewards from observed feedback and uses probabilistic sampling to balance exploration and exploitation \citep{russo2018tutorial}.<!--ref:russo2018tutorial--><!--anchor:section:2,3-->

Permission control also involves consequences that extend beyond the current decision. Keeping a valid authorization may avoid another interruption later, while revoking it too soon may force the assistant to ask again. Basic MAB formulations do not explicitly represent these action-dependent changes to authorization state. Value-based reinforcement learning (RL) methods, such as Double DQN, evaluate actions using state transitions and future rewards \citep{vanhasselt2016deep}.<!--ref:vanhasselt2016deep--><!--anchor:section:Background,Double Q-learning--> This distinction motivates sequential approaches to permission control. Any advantage over simpler policies, however, must be established empirically.

## Least Privilege and Authorization Management in Multi-Step Tasks

During execution, tool calls must remain within the permissions the user has granted. MiniScope derives required permissions from a task execution plan and a permission hierarchy. It constrains tool calls through user approval and an independent checker, with support for one-time, session-level, and persistent authorizations \citep{zhu2025miniscope}.<!--ref:zhu2025miniscope--><!--anchor:section:IV-B,IV-C--> Progent expresses tool-call policies as symbolic rules over tools and their arguments. It deterministically checks whether a proposed policy update would permit additional operations. Permission narrowing can take effect automatically, while expansion follows a configurable approval mechanism \citep{shi2026progent}.<!--ref:shi2026progent--><!--anchor:section:4.3,7--> MiniScope connects task requirements to authorization granularity, while Progent provides explicit control over changes to tool-call policies.

Authorization reuse affects the frequency of user interruptions. GAAP stores users' disclosure permissions and constrains subsequent data propagation through information-flow checks and persistent disclosure records. In experiments with consecutive tasks, retaining permission records reduced user interactions compared with clearing them after every task \citep{stanley2026gaap}.<!--ref:stanley2026gaap--><!--anchor:section:3.3,4.3-4.5,6.5--> Fewer interruptions can therefore reflect reuse of existing permissions rather than improved preference learning.

Permission to read data and permission to disclose it to another tool require separate consideration. CaMeL separates control flow from data flow and attaches metadata about sources and permitted recipients to data. These annotations support information-flow checks on subsequent tool calls \citep{debenedetti2025camel}.<!--ref:debenedetti2025camel--><!--anchor:section:4.2,4.3--> For example, a travel-planning agent may read a confirmation email to extract times and locations for a calendar entry. Permission to read that email does not automatically permit copying unrelated content into the calendar. The distinction concerns both which data the agent can access and where those data may subsequently be sent.

## Learning Privacy-Aware Behavior and Evaluating Execution

Privacy-aware training aims to reduce unnecessary disclosure and excessive privilege use in agent behavior. CI-RL trains language models with RL to distinguish information needed for a task from information that should not be disclosed \citep{lan2025contextual}.<!--ref:lan2025contextual--><!--anchor:section:Abstract--> ToolPrivBench examines whether agents select higher-privilege tools when lower-privilege alternatives suffice, or escalate privileges prematurely after temporary failures. Its authors use supervised fine-tuning and RL to improve these choices \citep{yang2026lower}.<!--ref:yang2026lower--><!--anchor:section:3,5.3--> Tu and Tu study excessive privilege use in executable terminal and Model Context Protocol (MCP) environments. Their approach combines task-specific permission requirements, execution auditing, and RL post-training \citep{tu2026task}.<!--ref:tu2026task--><!--anchor:section:III-A,III-B,III-D--> We instead study a separate permission policy for access scope and authorization duration. The policy uses ongoing feedback from the same user, without post-training the task language model.

Privacy-related responses can differ from behavior during task execution. PrivacyLens reports discrepancies between models' answers to privacy-norm questions and their disclosure behavior when carrying out user instructions. It extends evaluation to agent actions \citep{shao2024privacylens}.<!--ref:shao2024privacylens--><!--anchor:section:Abstract--> ToolEmu uses language models to emulate tool execution and assesses agent risks from the resulting traces \citep{ruan2024identifying}.<!--ref:ruan2024identifying--><!--anchor:section:Abstract--> Model responses and execution traces provide different evidence about privacy behavior.
