# Related Work

个人助理的权限管理需要同时处理两个相互关联的问题：理解用户愿意授予什么访问能力，以及限制这些能力在任务执行中如何被使用。本文关注二者之间的联系，即对同一用户持续反馈的学习，能否转化为更合理的权限范围与生命周期安排。这里需要区分学习带来的收益与授权记录复用带来的收益：已有系统仅通过保留实际授权，就能够减少连续任务中的重复确认。[GAAP](https://arxiv.org/abs/2604.19657)<!--ref:N2--><!--anchor:section:6.5--> 因而，本文所检验的不是能否记住用户的选择，而是在相同授权执行约束下，持续更新的策略能否比已有记忆规则和仅考虑当前请求的策略，更好地协调任务完成、用户打扰与不必要数据暴露。

## 从权限偏好预测到持续决策

利用用户历史辅助权限管理已有较长的研究基础。Liu 等的个性化隐私助理通过少量用户输入推荐移动应用权限设置；Wijesekera 等进一步结合访问上下文与既往决策推断用户偏好，在不确定时请求确认，并讨论随反馈增量更新模型。[Liu et al., 2016](https://www.usenix.org/conference/soups2016/technical-sessions/presentation/liu)<!--ref:R2--><!--anchor:section:Abstract-->；[Wijesekera et al., 2017](https://www.ieee-security.org/TC/SP2017/papers/278.pdf)<!--ref:R3--><!--anchor:page:1,12--> 这些研究说明，个性化判断、反馈更新和减少人工配置并非 Agent 时代才出现的问题；新的任务执行方式则要求重新考察权限决策的上下文和后果。

Wu 等的 *Towards Automating Data Access Permissions in AI Agents* 将这一问题推进到 Agent 场景。该工作通过用户研究识别数据访问决策的影响因素，并结合上下文学习与协同过滤建立权限预测助手，而不只提供问卷数据。其问卷包含四种回答，但主要预测评估采用“始终允许”和“永不允许”，排除了两类“下次再问”的回答。[Wu et al., S&P 2026](https://arxiv.org/html/2511.17959v1)<!--ref:R1--><!--anchor:section:V--> 对持续交互而言，当前是否允许与以后是否再次确认具有不同含义：两次相同的允许回答，可能对应一次性访问，也可能对应后续授权的复用。因此，本文保留四类回答，并区分既有信息下的预测能力与吸收同一用户新反馈所带来的增量价值。

不过，更完整的标签表示仍不足以回答权限在多步任务中应如何安排。即使正确预测了用户愿意持续授权，系统也仍需判断当前任务是否需要较宽的访问范围，以及保留该授权是否值得其带来的持续访问面。这使用户偏好与任务必要性成为相关但不同的决策依据，也意味着回答一致性的提高不能直接作为执行阶段隐私改善的证据。

## 从执行风险到受约束的权限适应

Agent 的工具执行风险为这一评价层次的区分提供了直接背景。Deng 等的 survey 将单 Agent 内部执行与工具调用列为独立安全问题，并提出严格工具审计和完整 Agent 评价的研究方向。[Deng et al., 2025](https://doi.org/10.1145/3716628)<!--ref:S0--><!--anchor:section:3.3,5--> 其中，ToolEmu 通过语言模型仿真工具与环境，检查执行轨迹的风险和有用性；R-Judge 则评价模型能否从交互记录中识别风险。[ToolEmu](https://arxiv.org/abs/2309.15817)<!--ref:S150--><!--anchor:section:2-3-->；[R-Judge](https://aclanthology.org/2024.findings-emnlp.79/)<!--ref:S219--><!--anchor:section:Abstract--> 前者提供执行过程的评价环境，后者测量风险判断能力，但二者都不能使一次正确判断自动成为实际执行约束。本文中的 mock 工具与任务检查用于观察权限决策的后果，不把仿真执行本身视为新的安全机制。

围绕执行过程中的隐私与安全，已有方法在不同位置实施干预。PrivacyAsst 通过加密或混洗保护提交给模型和工具的数据；TrustAgent 依据安全规约，在规划前、规划中和规划后结合学习与检查；CI-RL 则通过强化学习改善语言模型对适当信息披露的推理与选择。[PrivacyAsst](https://par.nsf.gov/servlets/purl/10501326)<!--ref:S225--><!--anchor:section:3-5-->；[TrustAgent](https://arxiv.org/html/2402.01586v4)<!--ref:S70--><!--anchor:section:3-->；[CI-RL](https://proceedings.neurips.cc/paper_files/paper/2025/hash/968591afcfe4ba889eccffb6a4ca2d45-Abstract-Conference.html)<!--ref:R8--><!--anchor:section:Abstract--> 这些工作分别保护数据表示、引导规则遵循或学习披露行为。本文选择的学习对象是权限决策：根据用户反馈与当前授权状态选择访问范围、询问、复用和收回时机。因此，“引入检查组件”或“使用强化学习保护隐私”不能单独构成与已有工作的区别。

权限管理系统也已经把最小权限与用户负担联系起来。MiniScope 根据 Agent 提交的执行计划和权限层级，用整数规划求解所需权限，并通过显式用户确认和独立检查器约束调用。它支持一次、会话和持续授权，还用三个月的模拟交互分析确认负担。[MiniScope](https://arxiv.org/abs/2512.11147)<!--ref:N1--><!--anchor:section:4.2-4.3,6.4--> 因此，长期模拟、授权复用或完整 Agent 架构都不是本文独有的研究内容。与本文更直接相关的是该工作在 §7.2–7.3 指出的困难：细粒度授权可能增加用户负担，而结合偏好预测减少确认又会受到预测可靠性的限制。本文据此关注持续学习的决策价值，但仍需通过与有记忆规则策略的比较，检验这种价值是否真实存在，而不能预设学习一定优于最小权限求解或授权复用。<!--ref:N1--><!--anchor:section:7.2-7.3-->

动态调整权限同样已有运行时机制支持。Progent 以工具和参数上的符号规则约束调用，并通过确定性检查区分权限收窄与扩张，允许自动收窄而要求扩张获得审批。[Progent v3](https://arxiv.org/html/2504.11703v3)<!--ref:R5--><!--anchor:section:2.2,5-6--> 这一设计解决了策略更新怎样受到执行边界约束的问题，但具备安全更新机制，并不自动回答何时收窄、保留多久或何时重新询问最适合某位用户。对于本文的序贯决策问题，当前收回权限可能减少暴露，却增加之后的确认需求；保留授权则可能产生相反后果。相关策略的比较需要保持执行边界一致，才能把这些跨步骤后果归因于决策方式。

授权边界还应与数据流保护区分。CaMeL 将控制流与数据流分离，并用数据关联的 capability 约束传播；GAAP 进一步以用户许可数据库和持久披露记录管理多步、跨任务的数据披露。[CaMeL](https://arxiv.org/html/2503.18813v1)<!--ref:R6--><!--anchor:section:4.2-4.3-->；[GAAP](https://arxiv.org/abs/2604.19657)<!--ref:N2--><!--anchor:section:3.3.3-3.3.4,4.3-4.5--> GAAP 对未来个性化决策的讨论也指出，以模型预测替代用户实际许可会损失其确定性保证。本文因而把偏好学习与授权执行分开：预测可以辅助请求和权限安排，但不直接产生新的授权。相应地，工具调用通过权限检查只能证明它符合所检查的授权条件，不能单独证明已读取的数据在后续任意文本或工具参数中都不会被不当披露。<!--ref:N2--><!--anchor:section:7-->
