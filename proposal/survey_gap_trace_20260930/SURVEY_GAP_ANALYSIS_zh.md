# 从 survey 到本文研究缺口：应当怎样论证

日期：2026-09-30。定向文献追溯与写作建议；不是新实验结果或首创性证明。

## 1. 核心判断

目前更可辩护的定位不是“没人研究 Agent 权限/隐私”，也不是“首次把 RL、ledger、monitor 放在一起”。现有工作已经覆盖个性化权限预测、动态收窄与扩权审批、授权持久化、长期用户模拟和运行时信息流保护。

我们要进一步回答的是：**在不让预测代替实际授权的条件下，利用同一用户连续提供的反馈来选择权限范围和生命周期，相对于已经会保存授权的规则策略，以及只考虑当前请求的策略，是否具有额外的决策价值，并能否改善任务完成、用户打扰与不必要暴露之间的权衡？**

这是一个可以设计对照实验回答的问题，不是通过搜不到完全同名系统就能确立的空白。把 DDQN 换成另一种算法，这个问题仍然成立。

## 2. 这篇 survey 提供什么，不提供什么

本地 ACM 版共 36 页。四个 gap 位于 pp.2–3；工具使用风险位于 §3.3；审计、完整系统评价和动态权限方向位于 §5，pp.25–26。

- 对我们最直接的动机是 **Gap 2 对应的工具执行与审计**。偏好变化与多轮反馈可以联系 Gap 1，但我们的实验不是在普遍解决模糊输入或恶意用户问题。
- Gap 4 可帮助说明外部实体风险，但本项目不能声称解决了任意不可信工具或完整数据流攻击。该 survey 的 §3.3 Agent2Tool 本身归在单 Agent 的 Action 风险下。
- §5 的动态权限表述主要围绕多 Agent 交互，不应原样迁移成“单 Agent 用户偏好学习尚未研究”的结论。
- 论文发表于 2025 年，但自述主要文献检索范围至 2024-04。它能建立问题背景，不能替代后续工作的核查。[Deng et al.](https://doi.org/10.1145/3716628)<!--ref:S0--><!--anchor:page:2-3,17,25-26-->

## 3. Survey 的引文如何进入 Related Work

**ToolEmu [150]：用来引出执行轨迹，而不是只看答案。** 它已经在仿真中检查 Agent 的工具使用风险和有用性，还展示过将限制时间的访问错误设为永久访问的例子。我们的 mock 不是仿真 Agent 评价这一思路的首创；作用是提供可重复的授权状态、工具状态与任务检查。[原论文](https://arxiv.org/abs/2309.15817)<!--ref:S150--><!--anchor:page:3-5-->

**R-Judge [219]：区分发现风险与执行约束。** 给定交互记录判断危险，不等于工具执行前确实有独立检查。它适合支持评价层次的区分，而不是作为学习权限策略的近邻。正式出处应引用 Findings of EMNLP 2024，不复制 survey 中的 ICLR 标注。[官方记录](https://aclanthology.org/2024.findings-emnlp.79/)<!--ref:S219--><!--anchor:section:Abstract-->

**PrivacyAsst [225]：区分保护提交的数据与减少不必要的数据访问。** 原文提供加密和混洗保护；本文的权限控制关注哪些数据应进入执行过程、授权应维持多大和多久。两者可以互补，不能直接用不同设定下的运行时间宣称本文更高效。[原论文](https://par.nsf.gov/servlets/purl/10501326)<!--ref:S225--><!--anchor:section:3,6,8-->

**TrustAgent [70]：承认检查组件和反馈学习已有先例。** 它把安全规则、逐步检查和模型学习接入 Agent。区别应放在学习对象与反馈含义：遵循安全规约不等于学习某个用户的权限偏好。[原论文](https://arxiv.org/html/2402.01586v4)<!--ref:S70--><!--anchor:section:3-->

CAMEL [89] 可解释 survey 的多 Agent 语境，但不宜硬塞进最接近工作。它与信息流防护系统 CaMeL 不是同一篇。

## 4. 必须补入的近邻：它们使我们的主张更精确

| 工作 | 已经覆盖的内容 | 本文不能仅凭什么声称贡献 |
|---|---|---|
| [Wu et al., S&P 2026](https://arxiv.org/html/2511.17959v1) | 用户研究、基于历史的权限偏好预测、权限管理助手 | 不能说别人只做数据，也不能把利用历史当作首次提出 |
| [Progent v3](https://arxiv.org/html/2504.11703v3) | 动态策略、自动收窄、扩权审批、确定性执行 | “能收放权限、有执行 monitor”不够 |
| [MiniScope](https://arxiv.org/abs/2512.11147) | 最小权限求解、一次/会话/持续授权、三个月模拟交互及确认负担 | “完整 Agent＋长期模拟＋权限状态”不够 |
| [GAAP](https://arxiv.org/abs/2604.19657) | 用户许可数据库、跨任务披露记录、独立 IFC、授权复用减少询问 | “ledger 记住反馈后询问变少”不等于学到了更好策略 |

最直接的开放方向依据是 MiniScope 的 PDF §7.2–7.3（pp.12–13）：更细粒度控制可能增加用户负担；结合用户偏好预测可能减少确认，但预测不可靠。GAAP 的 §7 也讨论个性化决策，并明确指出用 AI 决策替代实际用户许可会损失其保证。**研究困难因此不是“缺少一个 Agent 外壳”，而是如何在保留授权边界的同时利用不完全可靠的偏好估计。** 这句话是结合两篇原文与本文任务定义的综合推断，不是作者给本文的首创性背书。<!--ref:N1--><!--anchor:page:12-13--><!--ref:N2--><!--anchor:page:13-->

2026 年的 [How Agents Ask for Permission](https://arxiv.org/abs/2607.13718) 可补充当前权限系统的用户控制与执行背景，但应明确它是后续综述，不是用户这篇 ACM survey 的引文。<!--ref:N3--><!--anchor:section:5.1-5.2-->

## 5. “为什么还没解决”应写成具体难点

文献不能让我们推断其他研究者为什么没有选择这一课题。可以解释的是，已有设定的结论为何不能直接回答我们的问题。

1. **偏好估计不是合法授权。** 预测用户倾向于同意，有助于选择如何请求权限，但不能凭概率新增用户未授予的访问能力。真正可学习的是请求方案、范围、有效期、复用和收回时机，而不是让 RL 绕过授权。
2. **较少询问可能来自更宽、更久的授权。** 询问下降不是独立的好结果；若同时扩大了不必要访问面，不能称为更好的权衡。需区分任务必要性、用户同意与实际披露。
3. **一次动作会改变后续选择。** 收回暂时不需要的权限可减少持续访问面，却可能导致后续重新询问；保留权限有相反后果。这使生命周期选择具有序贯性，但并不保证 RL 必然胜过规则或 MAB。
4. **已有标签不包含完整执行后果。** 四回答数据适合评估偏好预测；它本身不提供每一步最小必要字段、工具执行结果或任务成功反事实。mock 与 oracle 提供受控检验条件，而不是把合成评价等同于真实部署。
5. **反馈并非免费且全可见。** 策略决定何时询问，也影响以后能观察到哪些用户回答。若给 RL 特权访问隐藏 persona 或未来回答，就不能归因于正常交互学习。

其中第 1–2 点与 MiniScope / GAAP 的设计权衡相呼应；第 3–5 点是根据本文设定作出的实验方法推断。

## 6. 对我们现有实验的直接含义

不需要因此否定 ICL、classification、MAB 和 DDQN 的整体路线；需要让每一层的证据各司其职。

- **RQ1**：用对齐标签、可见信息和数据划分的 ICL/分类回答偏好可预测性。四标签与 Wu 的主要二标签预测结果分开说明，不能直接按分数排名。
- **RQ2**：检验同一用户新增反馈的价值；冻结对照应拥有相同初始信息，不能把“没有历史”当作唯一对照。
- **RQ3**：至少增加“会记住实际授权但不训练”的规则策略，并与匹配条件下的冻结策略、短视策略比较。所有策略保持相同任务模型、工具、oracle、授权语义和 monitor。

需要特别说明：我们当前长期设计保留的是每个用户的模型与反馈记忆，任务之间可以重置授权与工具状态。这与 GAAP 的跨任务持久授权不是同一设置。论文应写“跨任务偏好学习、任务内权限生命周期控制”，除非后续确实实现并测试跨任务授权持久化。

隐私评价继续区分实际额外读取/披露与有效授权覆盖的累计访问面。它们是代理指标；一次授权有效且调用通过 monitor，不保证自由文本中不含其他敏感信息，更不等于完成了 IFC 或形式化隐私证明。

在现有证据下可以说已经建立了验证平台和提出了比较问题；不能说 DDQN 已经证明了更优的隐私—效率权衡。

## 7. 写作安排

Related Work 的逻辑建议是：**用户权限偏好可以辅助自动化决策 → 回答一致性不足以评价任务中的访问后果 → 现有系统已能最小化/保存/执行权限 → 尚需检验持续学习相对这些机制的增量价值**。

定位放在开头，并在 Wu、MiniScope、Progent、GAAP 的比较段落中展开；不在 section 最后补一个“本文贡献总结”。修订正文另存为 `RELATED_WORK_V3_zh.md`，旧 V2 和已同意的 Problem Setting 保持不变。
